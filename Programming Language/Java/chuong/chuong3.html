Chương 03 · Điều khiển luồng & mảng

Điều khiển luồng, mảng và nhập xuất

Chương này là bộ khung của mọi chương trình: rẽ nhánh, lặp, và lưu nhiều giá trị cùng kiểu. Điểm đáng chú ý nhất là switch — nó đã thay đổi hoàn toàn từ Java 14, từ một câu lệnh dễ gây bug (quên break) thành một biểu thức an toàn, và tới Java 21 thì trở thành công cụ khớp mẫu mạnh mẽ. Chúng ta học cả cách cũ (vì bạn sẽ gặp trong code có sẵn) lẫn cách mới (vì bạn nên viết như vậy).

Độ dài: ~1500 dòng Bài tập: 5 Quiz: 8 Prerequisites: Chương 1-2
🎯 Mục tiêu chương
  • Viết if/else if/else gọn gàng; biết dùng "trả về sớm" để giảm lồng nhau.
  • Phân biệt switch câu lệnh (cũ, có fall-through) và switch biểu thức (Java 14+, an toàn hơn).
  • Dùng pattern matching cho switch (Java 21) — thay thế chuỗi instanceof.
  • Nắm bốn kiểu vòng lặp và biết chọn cái nào cho tình huống nào.
  • Dùng break, continue, và nhãn để thoát vòng lặp lồng nhau.
  • Làm chủ mảng: khai báo, khởi tạo, mảng nhiều chiều, mảng răng cưa.
  • Sử dụng lớp tiện ích Arrays: sort, binarySearch, copyOf, fill, equals, toString.
  • Đọc dữ liệu bằng Scanner và tránh bẫy nextInt() + nextLine().
  • Định dạng đầu ra bằng printf / String.format — bảng chỉ định định dạng.

// ✅ Xử lý trường hợp loại trừ trước, thoát sớm
public String xuLy(DonHang don) {
    if (don == null)           return "Đơn không hợp lệ";
    if (!don.daThanhToan())   return "Chưa thanh toán";
    if (!don.conHang())       return "Hết hàng";
    return "Giao hàng";      // đường đi chính, nằm phẳng ở cuối
}

Kiểu viết thứ hai gọi là guard clause. Mỗi điều kiện loại trừ được xử lý và thoát ngay, để "đường đi chính" (happy path) nằm phẳng ở cuối — dễ đọc và dễ thêm điều kiện mới.

2. switch câu lệnh — cách cũ và cái bẫy của nó

SwitchCu.java 
int thu = 3;
String ten;

switch (thu) {
    case 2: ten = "Thứ hai"; break;
    case 3: ten = "Thứ ba";  break;
    case 4: ten = "Thứ tư";  break;
    default: ten = "Không rõ";
}
System.out.println(ten);   // Thứ ba
⚠️ Fall-through — quên break là chạy tiếp nhánh sau
FallThrough.java
int thu = 3;
switch (thu) {
    case 2: System.out.println("Thứ hai");
    case 3: System.out.println("Thứ ba");    // ← bắt đầu ở đây
    case 4: System.out.println("Thứ tư");    // ← rồi chạy tiếp!
    default: System.out.println("Không rõ");  // ← và tiếp nữa!
}
// In ra: Thứ ba / Thứ tư / Không rõ

Đây là hành vi cố ý của thiết kế (kế thừa từ C), nhưng trong 99% trường hợp nó là bug. Quên một chữ break ở giữa 20 nhánh là lỗi cực kỳ khó phát hiện khi đọc code.

Fall-through có một chỗ dùng hợp lý: gộp nhiều nhãn cùng xử lý một cách.

3. switch biểu thức (Java 14+) — cách nên viết

Java 14 chính thức đưa vào switch biểu thức: dùng mũi tên ->, không có fall-through, và trả về một giá trị.

SwitchMoi.java 
// ✅ Cách hiện đại — ngắn hơn, an toàn hơn
String ten = switch (thu) {
    case 2 -> "Thứ hai";
    case 3 -> "Thứ ba";
    case 4 -> "Thứ tư";
    default -> "Không rõ";
};                       // ⚠️ có dấu chấm phẩy — đây là BIỂU THỨC

// Gộp nhiều nhãn bằng dấu phẩy — không cần fall-through
int soNgay = switch (thang) {
    case 1, 3, 5, 7, 8, 10, 12 -> 31;
    case 4, 6, 9, 11             -> 30;
    case 2                        -> namNhuan ? 29 : 28;
    default -> throw new IllegalArgumentException("Tháng: " + thang);
};

// Nhánh nhiều dòng: dùng khối và yield để trả giá trị
String mota = switch (diem / 10) {
    case 10, 9 -> "Giỏi";
    case 8, 7 -> {
        System.out.println("Ghi log: học sinh khá");
        yield "Khá";             // yield trả giá trị cho khối
    }
    default -> "Cần cố gắng";
};

// Vẫn dùng được như CÂU LỆNH (không trả giá trị) — vẫn không fall-through
switch (lenh) {
    case "start" -> khoiDong();
    case "stop"  -> dungLai();
    default     -> System.out.println("Lệnh lạ");
}

"Bắt buộc đủ nhánh" — lợi ích lớn nhất mà ít người để ý

Với switch biểu thức, trình biên dịch bắt buộc mọi trường hợp phải được xử lý. Kết hợp với enum (hoặc sealed ở chương 5), điều này trở nên rất mạnh: khi bạn thêm một hằng số mới vào enum, mọi switch trên enum đó sẽ báo lỗi biên dịch cho tới khi bạn xử lý trường hợp mới.

DuNhanh.java
enum TrangThai { MOI, DANG_XU_LY, HOAN_THANH }

String mota = switch (tt) {
    case MOI         -> "Vừa tạo";
    case DANG_XU_LY  -> "Đang làm";
    case HOAN_THANH  -> "Xong";
};   // ✅ đủ mọi hằng số → KHÔNG cần default

// Mai sau thêm HUY vào enum → dòng trên báo lỗi biên dịch NGAY:
// error: the switch expression does not cover all possible input values

Đây là lý do không nên viết default khi switch trên enum: có default thì trình biên dịch im lặng, và bạn mất đi tấm lưới an toàn này.

4. Pattern matching cho switch (Java 21)

Java 21 cho phép switch khớp theo kiểu, không chỉ theo giá trị. Đây là thay đổi lớn nhất của switch kể từ khi ngôn ngữ ra đời.

PatternMatching.java 
// ❌ Cách cũ — chuỗi instanceof kèm ép kiểu thủ công
static String motaCu(Object o) {
    if (o instanceof Integer) {
        Integer i = (Integer) o;          // phải ép kiểu tay
        return "Số nguyên: " + i;
    } else if (o instanceof String) {
        String s = (String) o;
        return "Chuỗi dài " + s.length();
    } else if (o == null) {
        return "Rỗng";
    }
    return "Không rõ";
}

// ✅ Java 16+: pattern matching cho instanceof — biến tự khai báo
if (o instanceof String s && s.length() > 3) {
    System.out.println(s.toUpperCase());   // s đã sẵn kiểu String
}

// ✅ Java 21: pattern matching cho switch — gọn nhất
static String mota(Object o) {
    return switch (o) {
        case null          -> "Rỗng";          // switch xử lý được null!
        case Integer i     -> "Số nguyên: " + i;
        case Long l        -> "Số dài: " + l;
        case String s      -> "Chuỗi dài " + s.length();
        case int[] arr     -> "Mảng " + arr.length + " phần tử";
        default            -> "Kiểu khác: " + o.getClass().getSimpleName();
    };
}

// Có thêm điều kiện với "when" (guard)
static String phanLoai(Object o) {
    return switch (o) {
        case Integer i when i < 0      -> "Số âm";
        case Integer i when i == 0     -> "Số không";
        case Integer i                -> "Số dương";
        case String s when s.isBlank() -> "Chuỗi trắng";
        case String s                 -> "Chuỗi: " + s;
        default                        -> "Khác";
    };
}
⚠️ Thứ tự nhánh quan trọng — cụ thể trước, tổng quát sau

Giống catch hay if/else if, các nhánh case được kiểm tra từ trên xuống. Nếu đặt case Object o lên trước case String s, trình biên dịch báo lỗi ngay: "this case label is dominated by a preceding case label". Tương tự, case Integer i không có when phải đứng sau các nhánh Integer i when …. Java bắt được lỗi này lúc biên dịch — điểm cộng lớn so với chuỗi if/else nơi bạn phải tự để ý.

6. break, continue và nhãn

BreakContinue.java 
// break — thoát HẲN vòng lặp
for (int i = 0; i < 10; i++) {
    if (i == 5) break;
    System.out.print(i);      // 01234
}

// continue — bỏ qua phần còn lại, sang vòng tiếp theo
for (int i = 0; i < 10; i++) {
    if (i % 2 != 0) continue;

}

// ⚠️ break/continue chỉ tác động vòng lặp TRONG CÙNG
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 1) break;    // chỉ thoát vòng j, vòng i vẫn chạy
    }
}

💡 Nhãn hay tách hàm?

Nhãn là công cụ hợp pháp và đôi khi là cách rõ ràng nhất, nhưng nếu vòng lặp lồng nhau quá ba cấp hoặc logic bên trong dài, hãy cân nhắc tách thành phương thức riêng và dùng return — thường dễ đọc và dễ test hơn nhiều. Java không có goto (đây là từ khoá được giữ lại nhưng không dùng được); nhãn là thứ gần nhất, và nó bị giới hạn chỉ dùng với vòng lặp nên không thể tạo ra "mã spaghetti" như goto thật.

Mảng là object — và điều đó có hệ quả

Mảng trong Java là kiểu tham chiếu: nó nằm trên heap, có thể là null, và == so địa chỉ chứ không so nội dung. Nó cũng là kiểu duy nhất được tạo mà không cần class khai báo trước — int[], String[][] đều là kiểu hợp lệ mà JVM tự sinh.

MangLaObject.java
int[] x = {1, 2, 3};
int[] y = {1, 2, 3};
System.out.println(x == y);                // false — hai object khác nhau
System.out.println(x.equals(y));           // false ⚠️ mảng KHÔNG override equals!
System.out.println(Arrays.equals(x, y));    // true  ✅ cách đúng

System.out.println(x);                     // [I@1b6d3586  — vô dụng
System.out.println(Arrays.toString(x));   // [1, 2, 3]    ✅

Chuỗi [I@1b6d3586 đọc là: [ nghĩa là mảng, I là int, sau @ là mã băm dạng thập lục phân. Đây là toString() mặc định của Object — mảng không override nó.

    pascal[i][0] = pascal[i][i] = 1;
    for (int j = 1; j < i; j++) {
        pascal[i][j] = pascal[i-1][j-1] + pascal[i-1][j];
    }
}
System.out.println(Arrays.deepToString(pascal));
// [[1], [1, 1], [1, 2, 1], [1, 3, 3, 1], [1, 4, 6, 4, 1]]
📌 Java không có mảng hai chiều thật

int[][] thực chất là "mảng của các mảng" — mỗi hàng là một object riêng nằm rải rác trên heap. Điều này khác C, nơi mảng hai chiều là một khối bộ nhớ liên tục. Hệ quả: (1) mảng răng cưa là chuyện tự nhiên trong Java; (2) duyệt theo hàng nhanh hơn duyệt theo cột (do cache CPU); (3) tốn thêm bộ nhớ cho các con trỏ hàng.

Chuyển đổi switch cũ sang mới

Đoạn code sau viết theo kiểu Java 8 và có một bug do fall-through. Tìm bug, rồi viết lại bằng switch biểu thức.

static String tinhPhiVanChuyen(String vung, double kg) {
    double phi = 0;
    switch (vung) {
        case "NOI_THANH":
            phi = 15000;
            break;
        case "NGOAI_THANH":
            phi = 25000;
        case "TINH_KHAC":
            phi = 40000 + kg * 5000;
            break;
        case "QUOC_TE":
            phi = 200000 + kg * 50000;
            break;
    }
    return String.format("%,.0fđ", phi);
}
  • Gọi với ("NGOAI_THANH", 2) trả về gì? Đúng ra phải là gì?
  • Viết lại bằng switch biểu thức, thêm nhánh default ném IllegalArgumentException.
  • Nâng cấp: đổi String vung thành enum Vung, rồi bỏ default. Thêm một hằng số mới vào enum và quan sát trình biên dịch báo lỗi.
Gợi ý

Câu 3 minh hoạ giá trị lớn nhất của switch biểu thức: nó biến "quên xử lý trường hợp mới" từ một bug lúc chạy thành một lỗi biên dịch. Đây là lý do nên tránh default khi switch trên enum — có default thì trình biên dịch không còn cảnh báo được nữa.

Phân tích văn bản

Viết chương trình nhận một đoạn văn bản (nhiều dòng, kết thúc bằng dòng chỉ có END) và in báo cáo:

  • Số dòng, số từ, số ký tự (kể cả và không kể khoảng trắng).
  • Từ dài nhất và từ ngắn nhất.
  • Tần suất từng chữ cái a-z (không phân biệt hoa thường) — vẽ biểu đồ cột bằng ký tự █.
  • 10 từ xuất hiện nhiều nhất, kèm số lần.

Ràng buộc: chỉ dùng mảng, String, vòng lặp — chưa dùng HashMap hay Stream (sẽ làm lại bằng công cụ đó ở chương 8 và 10 để so sánh).

Gợi ý

Đếm chữ cái: mảng int[26], chỉ số là c - 'a' sau khi Character.toLowerCase(c). Nhớ kiểm tra c >= 'a' && c <= 'z' để bỏ qua dấu và ký tự đặc biệt.
Đếm từ mà không có HashMap: tách từ vào một mảng, rồi với mỗi từ duyệt mảng "từ duy nhất" đã thu thập — đây là O(n²), và chính sự chậm chạp đó là động lực để bạn học HashMap ở chương 8. Hãy đo thời gian với văn bản 10.000 từ để cảm nhận rõ.

Quiz

Q1

Fall-through trong switch là gì? Vì sao nó nguy hiểm và khi nào nó hữu ích?

Xem đáp án
✓ Đáp án

Fall-through là hành vi của switch câu lệnh (kiểu cũ, dùng dấu hai chấm): sau khi khớp một case, chương trình chạy tiếp mọi nhánh phía dưới cho tới khi gặp break hoặc hết khối.

Nguy hiểm vì quên một chữ break giữa hàng chục nhánh là lỗi rất khó phát hiện khi đọc code — nó không phải lỗi cú pháp, chương trình vẫn chạy và chỉ cho kết quả sai.

Hữu ích khi cố ý gộp nhiều nhãn cùng xử lý: case 1: case 3: case 5: soNgay = 31; break;.

switch biểu thức (Java 14+, dùng ->) loại bỏ hoàn toàn fall-through, và cho phép gộp nhãn gọn hơn bằng dấu phẩy: case 1, 3, 5 -> 31;. Đây là lý do nên chuyển sang cú pháp mới.

Q2

switch biểu thức hơn switch câu lệnh ở những điểm nào?

Xem đáp án
✓ Đáp án

Năm điểm, theo thứ tự quan trọng:

  • Bắt buộc đủ nhánh — trình biên dịch yêu cầu mọi trường hợp phải được xử lý. Với enum, thêm một hằng số mới sẽ làm mọi switch liên quan báo lỗi biên dịch. Đây là lợi ích lớn nhất.
  • Không có fall-through — loại bỏ hẳn một lớp bug.
  • Là biểu thức — trả về giá trị, gán thẳng vào biến, không cần khai báo biến trước rồi gán trong từng nhánh.
  • Gộp nhãn gọn — case 1, 2, 3 ->.
  • Phạm vi biến riêng từng nhánh — switch cũ dùng chung một phạm vi cho cả khối, dễ gây xung đột tên.

Nhánh nhiều dòng dùng khối và yield để trả giá trị: case A -> { … yield giaTri; }.

Q3

Khi nào dùng for cổ điển, khi nào dùng for-each?

Xem đáp án
✓ Đáp án

for-each là mặc định — ngắn hơn, không thể sai chỉ số, không thể gây ArrayIndexOutOfBoundsException, và diễn đạt đúng ý "duyệt qua mọi phần tử".

Dùng for cổ điển khi:

  • Cần chỉ số (in số thứ tự, so sánh phần tử i với i-1).
  • Cần sửa phần tử của mảng — trong for-each, biến lặp chỉ là bản sao (với kiểu nguyên thủy) nên gán vào nó không đổi mảng.
  • Cần duyệt ngược, hoặc bước nhảy khác 1.
  • Cần duyệt một phần của mảng.

Một giới hạn nữa của for-each: không được thêm/xoá phần tử của collection khi đang duyệt — sẽ ném ConcurrentModificationException. Dùng Iterator.remove() hoặc removeIf() thay thế (chương 7).

Q4

Vì sao arr.equals(arr2) cho false dù hai mảng cùng nội dung?

Xem đáp án
✓ Đáp án

Vì mảng không override equals(). Nó dùng bản cài đặt mặc định của Object, mà bản đó chỉ so sánh địa chỉ — hệt như ==. Hai mảng khác nhau luôn có địa chỉ khác nhau, nên kết quả luôn false.

SoSanhMang.java
int[] a = {1, 2}, b = {1, 2};
a == b                      // false
a.equals(b)                  // false ⚠️
Arrays.equals(a, b)          // true  ✅ 1 chiều
Arrays.deepEquals(x, y)      // ✅ nhiều chiều

Tương tự, System.out.println(arr) in ra [I@1b6d3586 (mã băm) chứ không phải nội dung — phải dùng Arrays.toString(arr) hoặc Arrays.deepToString(arr). Đây là hai trong số những nhầm lẫn phổ biến nhất của người mới học Java.

Q5

Bẫy Scanner.nextInt() + nextLine() là gì? Sửa thế nào?

Xem đáp án
✓ Đáp án

nextInt() chỉ đọc token số nguyên và để lại ký tự xuống dòng trong bộ đệm. Lần nextLine() tiếp theo gặp ngay ký tự đó, hiểu là "dòng đã hết", và trả về chuỗi rỗng mà không hề đợi người dùng gõ gì.

Cách sửa, theo thứ tự nên dùng:

  • Chỉ dùng nextLine() cho mọi thứ, rồi tự chuyển kiểu bằng Integer.parseInt(s.trim()). Nhất quán, không có ký tự sót, và bạn kiểm soát được lỗi định dạng bằng try/catch NumberFormatException.
  • Gọi thêm một sc.nextLine() ngay sau nextInt() để "nuốt" ký tự sót.
  • Dùng next() nếu chỉ cần một từ không có dấu cách.

Bẫy này tồn tại vì Scanner trộn hai mô hình đọc: theo token (next*) và theo dòng (nextLine). Chọn một mô hình và dùng nhất quán là cách phòng tránh triệt để.

Q6

Java có mảng hai chiều thật không? int[][] thực chất là gì?

Xem đáp án
✓ Đáp án

Không. int[][] là "mảng của các mảng int" — mảng ngoài chứa các tham chiếu, mỗi tham chiếu trỏ tới một mảng một chiều riêng biệt nằm rải rác trên heap. Điều này khác C, nơi mảng hai chiều là một khối bộ nhớ liên tục.

Ba hệ quả:

  • Mảng răng cưa là tự nhiên — mỗi hàng có độ dài riêng: new int[3][] rồi gán từng hàng. Tam giác Pascal là ví dụ điển hình.
  • Duyệt theo hàng nhanh hơn theo cột — các phần tử trong một hàng nằm liền nhau nên tận dụng được cache CPU; nhảy giữa các hàng thì không.
  • clone() chỉ sao chép nông — tạo mảng ngoài mới nhưng dùng chung các hàng cũ. Muốn bản sao thật phải clone() từng hàng.

Cũng vì vậy, m.length là số hàng, còn m[i].length là số cột của riêng hàng i — luôn dùng dạng thứ hai khi duyệt, để code chạy đúng cả với mảng răng cưa.

Q7

break ngoai; (nhãn) làm gì? Java có goto không?

Xem đáp án
✓ Đáp án

Nhãn cho phép break hoặc continue tác động lên một vòng lặp bên ngoài, thay vì chỉ vòng lặp trong cùng. Đặt nhãn trước vòng lặp (ngoai:) rồi dùng break ngoai; để thoát cả cụm.

  • break nhan; — thoát hẳn vòng lặp mang nhãn đó.
  • continue nhan; — sang lần lặp tiếp theo của vòng lặp mang nhãn đó.

Java không có goto. Từ khoá goto được giữ lại trong danh sách từ khoá (cùng với const) nhưng không dùng được — đây là quyết định thiết kế có chủ đích để tránh mã spaghetti. Nhãn là thứ gần goto nhất, nhưng nó bị giới hạn chỉ dùng với vòng lặp và chỉ nhảy ra ngoài, nên không tạo ra luồng điều khiển rối rắm được.

Thực tế: nếu thấy cần nhãn, hãy cân nhắc tách phần đó thành phương thức riêng và dùng return — thường dễ đọc và dễ test hơn.

Q8

%n và \n khác nhau thế nào? Khi nào khác biệt đó quan trọng?

Xem đáp án
✓ Đáp án

\n là một ký tự cố định — LF (mã 10), luôn luôn như vậy trên mọi hệ điều hành. %n là một chỉ định định dạng, được thay bằng ký tự xuống dòng của hệ điều hành đang chạy: LF trên Unix/macOS, CRLF (\r\n) trên Windows.

Khi nào quan trọng:

  • Ghi tệp văn bản mà người dùng Windows sẽ mở bằng Notepad hoặc Excel — dùng \n thì họ thấy một dòng dài liền tù tì.
  • Sinh tệp CSV — nhiều công cụ yêu cầu CRLF theo chuẩn RFC 4180.
  • Giao tiếp qua giao thức mạng — HTTP và SMTP quy định rõ CRLF.

Khi in ra terminal thì thường không khác biệt vì terminal hiện đại xử lý được cả hai. Lưu ý %n chỉ dùng được trong printf / String.format — trong println thì không cần vì nó đã tự thêm ký tự xuống dòng đúng của hệ thống (System.lineSeparator()).

Tổng kết

Sau chương 3, bạn đã nắm:

  • if: điều kiện phải là boolean; luôn dùng ngoặc nhọn; guard clause để giảm lồng nhau.
  • switch cũ: fall-through và nguy cơ của nó; gộp nhãn là cách dùng hợp lý duy nhất.
  • switch biểu thức (Java 14+): ->, yield, trả giá trị, và bắt buộc đủ nhánh.
  • Pattern matching (Java 21): case String s, when, xử lý null, kiểm tra thứ tự nhánh lúc biên dịch.
  • Bốn vòng lặp và tiêu chí chọn; giới hạn của for-each.
  • Nhãn để thoát vòng lặp lồng nhau; Java không có goto.
  • Mảng: là object, length là thuộc tính, kích thước cố định, int[][] là mảng của mảng.
  • Arrays: toString/deepToString, sort, binarySearch, copyOf, equals — và bẫy sao chép nông.
  • Scanner: bẫy nextInt+nextLine, mẫu đọc số an toàn.
  • printf: bảng chỉ định định dạng, in bảng thẳng hàng, %n thay \n.
