Tại sao học OS?

OS là nền tảng vô hình dưới mọi đoạn code. Không hiểu OS, bạn vẫn code được — nhưng:

  • Phỏng vấn: backend/DevOps/SRE đều hỏi: process vs thread, deadlock, virtual memory, file descriptor.
  • Debug production: hiểu OS giúp đọc strace, top, vmstat; tìm ra bug "vô lý" như memory leak, thread starvation.
  • Tối ưu hiệu năng: biết khi nào tạo thread, khi nào tạo process, khi nào cần shared memory thay vì pipe.
  • Hiểu công cụ: Docker, Node.js event loop, Kubernetes pod — tất cả xây trên OS primitives.

⚙️ Cách học hiệu quả nhất
Mở terminal Linux/macOS và thử thật: strace ls xem syscall thực, ps -eLf xem thread, htop xem process state. OS không thể học bằng cách "chỉ đọc" — nó là hệ thống đang chạy ngay dưới ngón tay bạn.

Xem trước — Process State Diagram

Đây là sơ đồ trạng thái process bạn sẽ học chi tiết ở Chương 02:

┌──────────────┐ admit │ │ exit ───────▶ │ NEW │ ──┐ │ │ │ └──────┬───────┘ │ │ scheduler │ ▼ │ ┌──────────────┐ │ │ │ │ │ READY │◀────┐ │ │ │ │ │ └──────┬───────┘ │ │ │ dispatch │ │ ▼ │ │ ┌──────────────┐ │ │ │ │ done│ ▼ │ RUNNING │─────┴───▶ ┌────────────┐ │ │ │ TERMINATED │ └──────┬───────┘ └────────────┘ │ I/O wait ▼ ┌──────────────┐ │ │ │ BLOCKED │ │ │ └──────────────┘ │ I/O ready └─────────────▶ READY

5 trạng thái: NEW (mới sinh), READY (sẵn sàng chạy), RUNNING (đang chạy trên CPU), BLOCKED (đợi I/O), TERMINATED (đã xong).

Cách dùng tài liệu này

  1. Đọc giáo trình tổng quan trước (10-15 phút).
