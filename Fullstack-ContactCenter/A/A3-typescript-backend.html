TypeScript cho Backend

JD yêu cầu "thành thạo TypeScript". Backend của một Contact Center có hàng trăm kiểu dữ liệu (Call, Agent, Ticket, Channel, Permission...) — TypeScript giúp bắt lỗi lúc compile thay vì để khách hàng gặp lỗi lúc runtime. Đây cũng là nền tảng bắt buộc để dùng NestJS.

🎯 Học xong chương này bạn sẽ

• Nắm hệ thống kiểu: union, intersection, unknown vs any vs never.

• Thành thạo Generics và Utility Types — công cụ tái sử dụng kiểu mạnh nhất.

• Viết type guard, discriminated union để mô hình hóa trạng thái (vd vòng đời cuộc gọi).

• Hiểu Decorators & metadata — cơ chế NestJS dùng cho @Controller, @Injectable...

• Cấu hình tsconfig ở chế độ strict đúng chuẩn production.

① Vì sao dùng TypeScript ở backend?

🛡️ An toàn kiểu

Bắt lỗi sai kiểu, thiếu field, gọi sai hàm ngay lúc compile — trước khi deploy.

🧭 Tự tài liệu hóa

Kiểu chính là tài liệu sống. IDE gợi ý, autocomplete chính xác từng property.

🔧 Refactor an toàn

Đổi tên/đổi cấu trúc, compiler chỉ ra mọi nơi bị ảnh hưởng.

🏗️ Bắt buộc cho NestJS

NestJS dựa hoàn toàn vào TypeScript + decorators + DI.

TypeScript là superset của JavaScript: mọi code JS hợp lệ đều là TS hợp lệ. Nó compile về JavaScript thuần (kiểu bị xóa — "type erasure"), không tồn tại lúc runtime.

⚠️ any vs unknown

Cả hai nhận mọi giá trị, nhưng any cho bạn làm bất cứ gì (mất an toàn), còn unknown buộc bạn kiểm tra/ép kiểu trước khi dùng. Khi nhận payload JSON từ client, dùng unknown rồi validate.

③ Interface vs Type

interface.ts
interface Agent {
  id: string;
  name: string;
  status: AgentStatus;
  skills?: string[];   // optional

}
// có thể "extends" và merge khai báo
interface Supervisor extends Agent {

type.ts
type AgentStatus = 'available' | 'busy';

type Agent = {
  id: string;
  status: AgentStatus;

// type giỏi: union, tuple, mapped, conditional
type ID = string | number;
💡 Chọn cái nào?

Quy ước phổ biến: dùng interface cho hình dạng object & khi cần extends/implements (đặc biệt trong NestJS/OOP); dùng type cho union, tuple, mapped type, conditional type. Khác biệt nhỏ: interface có thể "declaration merging", type thì không.

⑤ Generics — tái sử dụng kiểu

Generics cho phép viết hàm/lớp/kiểu hoạt động với nhiều kiểu khác nhau mà vẫn giữ an toàn kiểu. Đây là khái niệm nâng cao hay được hỏi để phân biệt ứng viên Junior vs Middle.

generics.tsTypeScript
// Kiểu phản hồi API dùng chung cho mọi entity
interface ApiResponse<T> {
  data: T;
  success: boolean;
  timestamp: number;
}
type AgentResponse = ApiResponse<Agent>;
type CallList     = ApiResponse<Call[]>;

// Hàm generic giữ quan hệ kiểu input → output
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
const a = first(agents); // a: Agent | undefined ✅ tự suy ra

// Generic constraint: T phải có field 'id'
function byId<T extends { id: string }>(items: T[], id: string): T | undefined {
  return items.find(x => x.id === id);
}

// Generic repository — pattern hay gặp ở backend
class Repository<T extends { id: string }> {
  private store = new Map<string, T>();
  save(item: T) { this.store.set(item.id, item); }
  get(id: string): T | undefined { return this.store.get(id); }
}

⑦ Type narrowing, Type Guard & Discriminated Union

Narrowing là việc TypeScript thu hẹp kiểu dựa vào điều kiện. Discriminated union là cách mô hình hóa state máy (state machine) cực mạnh — lý tưởng cho vòng đời cuộc gọi.

discriminated-union.tsTypeScript
// Mỗi trạng thái có field 'kind' phân biệt + dữ liệu riêng
type CallState =
  | { kind: 'ringing'; from: string }
  | { kind: 'active';  agentId: string; startedAt: Date }
  | { kind: 'ended';   duration: number; reason: string };

function describe(call: CallState): string {
  switch (call.kind) {
    case 'ringing': return `Đang đổ chuông từ ${call.from}`;
    case 'active':  return `Đang nói chuyện với agent ${call.agentId}`;
    case 'ended':   return `Kết thúc sau ${call.duration}s`;
    default:
      const _exhaustive: never = call; // ✅ ép xử lý hết mọi case
      return _exhaustive;
  }
}

// Custom type guard
function isActive(c: CallState): c is { kind: 'active'; agentId: string; startedAt: Date } {
  return c.kind === 'active';
}

⑧ Decorators — nền tảng của NestJS

Decorator là hàm "gắn nhãn" lên class/method/property để thêm metadata hoặc thay đổi hành vi. NestJS dùng dày đặc: @Controller, @Injectable, @Get, @Body... Hiểu cơ chế giúp bạn không "dùng như phép thuật".

decorator.tsTypeScript
// Class decorator đơn giản (cần "experimentalDecorators": true)
function LogClass(target: Function) {
  console.log(`Khởi tạo class ${target.name}`);
}

// Method decorator — đo thời gian xử lý cuộc gọi
function Measure(_t: any, key: string, desc: PropertyDescriptor) {
  const original = desc.value;
  desc.value = async function (...args: any[]) {
    const t0 = Date.now();
    const result = await original.apply(this, args);
    console.log(`${key} mất ${Date.now() - t0}ms`);
    return result;
  };
}

@LogClass
class CallService {
  @Measure
  async route(callId: string) { /* ... */ }
}

💡 Luôn bật "strict": true

Chế độ strict bật một loạt cờ kiểm tra (strictNullChecks, noImplicitAny...). Đây là tiêu chuẩn production và là điều phỏng vấn viên mong đợi bạn dùng. Code không strict thực chất chỉ là "JS có chú thích".

⚠️ Lỗi thường gặp & Best practices

🚫 Lạm dụng any

Dùng unknown + validate. any làm TS vô nghĩa.

🚫 Ép kiểu as bừa

as nói dối compiler — chỉ dùng khi chắc chắn, ưu tiên type guard.

🚫 Tin kiểu lúc runtime

Kiểu bị xóa khi compile → vẫn phải validate dữ liệu ngoài (zod/class-validator).

🚫 Quên xử lý null

Bật strictNullChecks, dùng optional chaining ?. và ??.

🚫 enum nặng nề

Cân nhắc union literal hoặc as const thay enum khi chỉ cần giá trị.

🚫 Lặp định nghĩa kiểu

Tận dụng Utility Types & Generics thay vì copy interface.

🧪 Bài tập

🧪 Bài 1 — Generic & constraint

Viết hàm generic groupBy<T>(items: T[], key: keyof T) trả về Record<string, T[]>. Áp dụng để nhóm agent theo status.

Xem gợi ý 
function groupBy<T>(items: T[], key: keyof T): Record<string, T[]> {
  return items.reduce((acc, item) => {
    const k = String(item[key]);
    (acc[k] ??= []).push(item);
    return acc;
  }, {} as Record<string, T[]>);
}
🧪 Bài 2 — Discriminated union

Mô hình hóa type ChannelMessage cho 3 kênh: email (subject, body), sms (phone, text), chat (sessionId, text). Viết hàm render(msg) dùng exhaustiveness check.

Xem gợi ý

Dùng field phân biệt channel: 'email' | 'sms' | 'chat', switch trên nó, nhánh default gán vào biến never để compiler ép xử lý đủ.

Ngân hàng câu hỏi phỏng vấn

TypeScript — phần được kiểm tra kỹ vì JD ghi rõ "thành thạo".

Q1TypeScript là gì? Lợi ích so với JavaScript?Junior›

Trả lời: TS là superset của JS, thêm hệ thống kiểu tĩnh, compile về JS thuần. Lợi ích: bắt lỗi lúc compile, autocomplete/IDE tốt hơn, refactor an toàn, code tự tài liệu hóa, bắt buộc cho NestJS/Angular.

Q2Phân biệt interface và type.Junior›

Trả lời: Cả hai mô tả hình dạng. interface hỗ trợ extends/implements & declaration merging, hợp cho object/OOP. type linh hoạt hơn: union, tuple, mapped, conditional type — nhưng không merge được. Thực tế dùng interface cho object, type cho union/biến đổi kiểu.

Q3any, unknown, never khác nhau thế nào?Middle›

Trả lời: any tắt kiểm tra kiểu (nguy hiểm). unknown nhận mọi giá trị nhưng buộc narrow trước khi dùng (an toàn). never là kiểu không có giá trị nào — dùng cho hàm luôn throw hoặc nhánh không thể xảy ra (exhaustiveness check).

Q4Generics là gì? Vì sao cần? Cho ví dụ thực tế.Middle›

Trả lời: Generics cho phép viết code hoạt động với nhiều kiểu mà vẫn giữ an toàn kiểu, giữ quan hệ input→output. Ví dụ: ApiResponse<T> dùng chung cho mọi entity, Repository<T> generic, hàm first<T>(arr): T. Có thể giới hạn bằng extends (constraint).

Q5Discriminated union là gì? Khi nào dùng?Middle›

Trả lời: Là union các object có chung một field "phân biệt" (vd kind/type) với giá trị literal khác nhau. Khi switch trên field đó, TS tự narrow kiểu từng nhánh. Lý tưởng để mô hình state machine (vòng đời cuộc gọi: ringing/active/ended), kết hợp never để ép xử lý hết case.

Q6Type guard là gì? Viết một custom type guard.Middle›

Trả lời: Type guard là biểu thức/hàm giúp TS narrow kiểu. Có sẵn (typeof, instanceof, in) và custom dùng cú pháp arg is Type: function isAgent(x: unknown): x is Agent { return typeof x === 'object' && x !== null && 'id' in x; }.

Q7Decorator hoạt động ra sao? NestJS dùng nó để làm gì?Middle›

Trả lời: Decorator là hàm nhận target (class/method/property) và có thể gắn metadata hoặc bọc hành vi. NestJS dùng decorator để khai báo cấu trúc (@Module, @Controller, @Injectable), định tuyến (@Get), trích xuất dữ liệu (@Body, @Param) và đọc metadata cho Dependency Injection. Cần bật experimentalDecorators + emitDecoratorMetadata.

Q8Vì sao vẫn cần validate dữ liệu runtime dù đã có TypeScript?Middle›

Trả lời: Vì kiểu TS bị xóa khi compile (type erasure) — không tồn tại lúc runtime. Dữ liệu từ client/API/DB có thể không khớp kiểu khai báo. Phải validate bằng zod, class-validator, hoặc kiểm tra thủ công ở ranh giới hệ thống (controller, message handler).

Q9So sánh enum với union literal / as const.Senior›

Trả lời: enum tạo object runtime (tốn code, có thể gây nhầm với numeric enum). Union literal ('a' | 'b') chỉ tồn tại compile-time, nhẹ, dễ kết hợp. as const giúp suy ra literal type từ mảng/object hằng. Xu hướng hiện đại ưu tiên union literal trừ khi thật sự cần object enum lúc runtime.

Q10strict mode bật những gì? Vì sao nên dùng?Middle›

Trả lời: strict: true bật một nhóm cờ: strictNullChecks, noImplicitAny, strictFunctionTypes, strictBindCallApply... Giúp bắt lỗi null/undefined, cấm any ngầm, tăng độ an toàn. Đây là tiêu chuẩn production; không bật strict thì TS mất phần lớn giá trị.
