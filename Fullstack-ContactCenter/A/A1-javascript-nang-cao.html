JavaScript chuyên sâu cho Backend

Ôn lại JavaScript ở tầng cơ chế hoạt động — không phải cú pháp, mà là cách ngôn ngữ thực sự vận hành: closure, this, prototype, scope, module. Đây là nền tảng để hiểu Node.js, NestJS và mọi đoạn code bất đồng bộ phía sau.

🎯 Học xong chương này bạn sẽ

• Giải thích được chính xác closure, TDZ, hoisting và this trong mọi ngữ cảnh.

• Phân biệt primitive vs reference, hiểu vì sao === luôn được ưu tiên.

• Nắm prototype chain & cú pháp class hiện đại — gốc của OOP trong Node/Nest.

• Tự tin trả lời các câu hỏi phỏng vấn JS "bẫy" thường gặp với Junior Fullstack.

💼 Vì sao quan trọng với hệ thống Contact Center?

Backend của một Contact Center xử lý hàng nghìn sự kiện đồng thời (cuộc gọi đến, tin nhắn chat, cập nhật trạng thái agent). Toàn bộ logic này dựa trên callback, closure và event-driven — nếu không hiểu rõ JS ở tầng cơ chế, bạn sẽ tạo ra bug rò rỉ bộ nhớ, mất ngữ cảnh this, hoặc race condition rất khó debug.

① Kiểu dữ liệu & so sánh giá trị

JavaScript có 7 kiểu primitive và 1 kiểu object. Hiểu rõ ranh giới này quyết định cách bạn truyền, sao chép và so sánh dữ liệu.

Reference

Primitive vs Reference — cái bẫy kinh điển

value-vs-reference.jsJavaScript
// Primitive: sao chép GIÁ TRỊ
let a = 10;
let b = a;        // b là bản sao độc lập
b = 20;
console.log(a, b); // 10 20  ✅ a không đổi

// Reference: sao chép ĐỊA CHỈ (cùng trỏ tới 1 object)
const agent1 = { name: 'An', status: 'available' };
const agent2 = agent1;       // KHÔNG sao chép, chỉ copy con trỏ
agent2.status = 'busy';
console.log(agent1.status); // 'busy' ⚠️ agent1 cũng đổi!
⚠️ Hệ quả thực tế

Khi bạn lưu danh sách agent đang online trong một mảng và "sao chép" để gửi qua API, nếu chỉ gán const copy = agents thì mọi thay đổi vẫn ảnh hưởng bản gốc. Phải clone đúng cách: structuredClone(obj), {...obj} (nông), hoặc JSON.parse(JSON.stringify(obj)) (sâu, nhưng mất Date/undefined).

== vs === và type coercion

== thực hiện ép kiểu ngầm (coercion) trước khi so sánh — nguồn gốc của vô số bug. Luôn dùng === trừ khi bạn cố tình kiểm tra null/undefined cùng lúc bằng == null.

coercion.jsJavaScript
0 == ''          // true  😱
0 == '0'         // true
'' == '0'        // false (!) — không bắc cầu
null == undefined // true
[] == false      // true
NaN === NaN      // false — dùng Number.isNaN()

// Quy tắc vàng: dùng === ; chỉ "== null" để gộp null & undefined
if (agent.endedAt == null) { /* cuộc gọi chưa kết thúc */ }

Falsy values cần thuộc lòng

Chỉ có 8 giá trị falsy: false, 0, -0, 0n, "", null, undefined, NaN. Mọi thứ còn lại (kể cả [], {}, "0") đều truthy.

② Scope, Hoisting & TDZ

Scope = vùng mà một biến "nhìn thấy được". JavaScript có 3 loại: global, function, và block (từ ES6 với let/const).

🌍 var

Function-scoped, được hoisted lên đầu hàm với giá trị undefined. Tránh dùng.

📦 let

Block-scoped, có TDZ, có thể gán lại. Dùng khi giá trị thay đổi.

🔒 const

Block-scoped, có TDZ, không gán lại (nhưng object bên trong vẫn mutable). Mặc định nên dùng.

Hoisting & Temporal Dead Zone (TDZ)

Hoisting: khai báo được "kéo" lên đầu scope khi biên dịch. Nhưng let/const tuy được hoisted lại nằm trong TDZ — không thể truy cập trước dòng khai báo.

hoisting.jsJavaScript
console.log(callCount); // undefined (var được hoisted)
var callCount = 5;

console.log(maxAgents); // ❌ ReferenceError: Cannot access before initialization
let maxAgents = 10;   // ← biến nằm trong TDZ tới dòng này

// Function declaration được hoisted TOÀN BỘ (gọi được trước khi định nghĩa)
routeCall();                // ✅ chạy được
function routeCall() { /* ... */ }

// Function expression thì KHÔNG
routeChat();                // ❌ TypeError: routeChat is not a function
const routeChat = () => {};

③ Closure — "trái tim" của JavaScript

Closure là khi một hàm "nhớ" và tiếp tục truy cập được các biến ở scope nơi nó được định nghĩa, ngay cả khi hàm đó được gọi ở nơi khác. Đây là cơ chế nền tảng của private state, callback, currying, memoization — và xuất hiện ở mọi nơi trong Node.js.

closure-counter.jsJavaScript
// Bộ đếm cuộc gọi cho mỗi agent — state riêng tư, không lộ ra ngoài
function createCallCounter() {
  let count = 0;            // biến riêng tư, "đóng gói" trong closure
  return {
    increment() { count++; return count; },
    get()       { return count; }
  };
}

const agentA = createCallCounter();
agentA.increment(); // 1
agentA.increment(); // 2
console.log(agentA.get());  // 2
console.log(agentA.count);    // undefined — không truy cập trực tiếp được ✅

Ứng dụng thực tế: rate limiter cho API

rate-limiter.jsJavaScript
// Giới hạn số request mỗi agent được gửi trong 1 cửa sổ thời gian
function createRateLimiter(maxCalls, windowMs) {
  const hits = new Map(); // closure giữ state qua nhiều lần gọi
  return function allow(agentId) {
    const now = Date.now();
    const times = (hits.get(agentId) || []).filter(t => now - t < windowMs);
    if (times.length >= maxCalls) return false;
    times.push(now);
    hits.set(agentId, times);
    return true;
  };
}

const limiter = createRateLimiter(5, 1000); // 5 req / giây
if (!limiter('agent-42')) throw new Error('Too many requests');
🐛 Bẫy closure trong vòng lặp (câu hỏi phỏng vấn kinh điển)
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3 ❌
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2 ✅

var chỉ có một binding dùng chung cho cả vòng lặp; let tạo binding mới mỗi vòng, nên mỗi closure bắt đúng giá trị.

④ this & cơ chế binding

this không phụ thuộc vào nơi hàm được định nghĩa, mà vào cách hàm được gọi. Đây là nguồn gây bug số một khi truyền method làm callback.

Cách gọithis trỏ tớiVí dụ
Gọi thườngundefined (strict) / globalfn()
MethodObject đứng trước dấu chấmobj.fn()
newObject mới được tạonew Fn()
call/apply/bindTham số đầu bạn truyềnfn.call(ctx)
Arrow functionKế thừa từ scope cha (lexical)() => this
this-binding.jsJavaScript
class CallQueue {
  constructor() { this.calls = []; }

  add(call) { this.calls.push(call); }

  // Method thường: mất 'this' khi truyền làm callback
  processAll() { this.calls.forEach(function(c) {
    // ❌ 'this' ở đây KHÔNG phải instance — là undefined
  }); }
}

const q = new CallQueue();
const add = q.add;
add({ id: 1 }); // ❌ TypeError: Cannot read 'push' of undefined — 'this' bị mất

// 3 cách sửa:
const bound = q.add.bind(q);     // (1) bind cứng
q.calls.forEach(c => this);     // (2) arrow giữ this
// (3) class field: process = () => {...} luôn bind vào instance
💡 Quy tắc thực dụng

Trong class của NestJS/Node, khi cần truyền method làm event handler (vd socket.on('msg', this.onMsg)), hãy dùng arrow function class field hoặc .bind(this) trong constructor để không mất ngữ cảnh.

⑤ Prototype, kế thừa & class

JavaScript dùng prototype-based inheritance: mỗi object có liên kết ẩn [[Prototype]] tới object khác. Khi truy cập thuộc tính không tồn tại, JS đi ngược prototype chain để tìm. class chỉ là "lớp áo cú pháp" (syntactic sugar) cho cơ chế này.

prototype.jsJavaScript
class Agent {
  constructor(name) { this.name = name; this.status = 'available'; }
  greet() { return `Agent ${this.name}`; }   // nằm trên Agent.prototype (dùng chung)
}

class Supervisor extends Agent {
  constructor(name, team) { super(name); this.team = team; }
  greet() { return super.greet() + ` (Supervisor of ${this.team})`; }
}

const s = new Supervisor('Lan', 'Sales');
s.greet(); // "Agent Lan (Supervisor of Sales)"

// Prototype chain: s → Supervisor.prototype → Agent.prototype → Object.prototype → null
s instanceof Agent;            // true
Object.getPrototypeOf(s) === Supervisor.prototype; // true
ℹ️ Method dùng chung — vì sao quan trọng

Method khai báo trong class nằm trên prototype, nên 10.000 agent chỉ chia sẻ 1 bản greet thay vì mỗi instance giữ một bản sao → tiết kiệm bộ nhớ. Ngược lại, arrow-function class field tạo bản riêng mỗi instance (đánh đổi để bind this).

⑥ Module: ESM vs CommonJS

Node.js hỗ trợ 2 hệ module. Hiểu khác biệt giúp bạn tránh lỗi require is not defined / Cannot use import outside a module thường gặp khi cấu hình dự án.

CommonJS (.cjs)
// export
module.exports = { routeCall };
exports.helper = helper;

// import (đồng bộ)
const { routeCall } = require('./router');
ES Module (.mjs)
// export
export { routeCall };
export default Router;

// import (tĩnh, hoisted)
import { routeCall } from './router.js';

⑦ Hàm bậc cao & tính bất biến

Phong cách functional (map/filter/reduce, pure function, immutability) giúp code backend dễ test, dễ suy luận và an toàn với dữ liệu chia sẻ — cực kỳ quan trọng trong hệ thống nhiều luồng sự kiện.

functional.jsJavaScript
const agents = [
  { name: 'An',  status: 'available', calls: 3 },
  { name: 'Lan', status: 'busy',      calls: 7 },
  { name: 'Huy', status: 'available', calls: 1 },
];

// Pure: không sửa input, luôn trả cùng output với cùng input
const available = agents
  .filter(a => a.status === 'available')
  .sort((x, y) => x.calls - y.calls); // agent rảnh nhất lên đầu (least-busy routing)

const totalCalls = agents.reduce((sum, a) => sum + a.calls, 0); // 11

// Bất biến: tạo bản mới thay vì sửa tại chỗ
const updated = agents.map(a =>
  a.name === 'An' ? { ...a, status: 'busy' } : a
);

⚠️ Lỗi thường gặp & Best practices

🚫 Dùng == tùy tiện

Luôn dùng ===. Chỉ == null khi cố ý gộp null/undefined.

🚫 Mutate object chia sẻ

Dùng spread/structuredClone. Tránh sửa trực tiếp state dùng chung.

🚫 Mất this khi truyền method

Dùng arrow class field hoặc .bind(this).

🚫 Lạm dụng var

Dùng const mặc định, let khi cần gán lại.

🚫 So sánh NaN

Dùng Number.isNaN(), không dùng === NaN.

🚫 Closure giữ tham chiếu lớn

Closure giữ biến → có thể gây rò rỉ bộ nhớ nếu giữ object lớn không cần thiết.

🧪 Bài tập

🧪 Bài 1 — Closure: bộ nhớ trạng thái agent

Viết hàm createAgentSession() trả về object với login(), logout(), isOnline(). Trạng thái online phải riêng tư, không truy cập trực tiếp được từ bên ngoài.

Xem gợi ý lời giải 
function createAgentSession() {
  let online = false; // riêng tư nhờ closure
  return {
    login()    { online = true; },
    logout()   { online = false; },
    isOnline() { return online; }
  };
}
🧪 Bài 2 — this: sửa bug callback

Cho class Dispatcher có method dispatch() được truyền vào setInterval(d.dispatch, 1000) nhưng báo lỗi mất this. Hãy nêu 2 cách sửa.

Xem gợi ý lời giải

(1) setInterval(() => d.dispatch(), 1000) — bọc trong arrow giữ ngữ cảnh. (2) Khai báo dispatch = () => {...} dạng class field để luôn bind vào instance. (3) setInterval(d.dispatch.bind(d), 1000).

Ngân hàng câu hỏi phỏng vấn

Các câu hỏi JavaScript thường gặp cho vị trí Fullstack — kèm đáp án mẫu & "bẫy".

Q1Closure là gì? Cho một ví dụ thực tế bạn từng dùng.Junior›

Trả lời: Closure là khả năng một hàm "ghi nhớ" và truy cập các biến ở scope nơi nó được định nghĩa, kể cả khi được gọi ở scope khác. Về bản chất, hàm con giữ tham chiếu tới môi trường biến (lexical environment) của hàm cha.

Ví dụ thực tế: tạo bộ đếm riêng tư, rate limiter, memoization cache, hoặc factory function trả về handler đã "gắn" sẵn cấu hình (vd createLogger(serviceName)).

⚠️ Bẫy: hỏi tiếp "closure có thể gây memory leak không?" → Có, nếu closure giữ tham chiếu tới object lớn không còn cần (vd event listener không gỡ), GC không thể thu hồi.

Q2Phân biệt var, let, const. TDZ là gì?Junior›

Trả lời: var function-scoped, được hoisted với giá trị undefined, cho phép redeclare. let/const block-scoped, không redeclare. const không cho gán lại binding (nhưng object bên trong vẫn mutable).

TDZ (Temporal Dead Zone): khoảng từ đầu block tới dòng khai báo let/const, trong đó biến tồn tại nhưng truy cập sẽ ném ReferenceError. Điều này buộc code phải khai báo trước khi dùng.

Q3Sự khác nhau giữa primitive và reference type? Truyền tham số hoạt động ra sao?Junior›

Trả lời: Primitive (string, number, boolean, null, undefined, symbol, bigint) lưu trực tiếp giá trị, truyền/gán theo bản sao giá trị. Reference (object, array, function) lưu địa chỉ, truyền/gán theo bản sao tham chiếu → sửa qua biến này ảnh hưởng biến kia.

JavaScript luôn truyền tham số theo giá trị, nhưng với object thì "giá trị" đó là con trỏ → giống pass-by-reference khi mutate, nhưng gán lại biến thì không ảnh hưởng bên ngoài.

⚠️ Bẫy: clone nông ({...obj}) không sao chép object lồng nhau — cần structuredClone cho deep clone.

Q4Giải thích this trong JavaScript. Có những cách nào để kiểm soát nó?Middle›

Trả lời: this được xác định lúc gọi hàm, không phải lúc định nghĩa. Quy tắc: gọi thường → undefined/global; method → object trước dấu chấm; new → instance mới; call/apply/bind → giá trị truyền vào; arrow function → kế thừa lexical từ scope cha.

Kiểm soát: fn.call(ctx, ...args), fn.apply(ctx, argsArray), fn.bind(ctx) (tạo hàm mới đã gắn cứng), hoặc dùng arrow function.

Q5== khác === thế nào? Khi nào chấp nhận dùng ==?Junior›

Trả lời: === so sánh nghiêm ngặt (cả kiểu lẫn giá trị). == ép kiểu ngầm trước khi so sánh → dễ gây kết quả bất ngờ (0 == '' là true). Quy ước: luôn dùng ===.

Trường hợp chấp nhận ==: kiểm tra x == null để gộp cả null và undefined trong một biểu thức.

Q6Prototype chain là gì? class trong JS có phải kế thừa thực sự không?Middle›

Trả lời: Mỗi object có liên kết [[Prototype]] tới object khác. Khi truy cập thuộc tính, JS tìm trên object, không thấy thì đi ngược chuỗi prototype tới khi gặp hoặc tới null.

class là syntactic sugar trên prototype — không phải kế thừa lớp kiểu Java. extends thiết lập prototype chain, super gọi constructor/method cha. Bản chất vẫn là prototype-based.

Q7ESM và CommonJS khác nhau ra sao? Khi nào gặp lỗi "Cannot use import outside a module"?Middle›

Trả lời: CommonJS (require/module.exports) tải đồng bộ lúc runtime, mặc định trong Node. ESM (import/export) là chuẩn tĩnh, phân tích lúc parse, hỗ trợ tree-shaking & top-level await.

Lỗi xuất hiện khi dùng cú pháp import trong file được Node hiểu là CommonJS. Khắc phục: thêm "type": "module" vào package.json, đổi đuôi .mjs, hoặc dùng bundler/transpiler.

Q8Vì sao output của vòng lặp với var + setTimeout lại sai? Cách sửa?Middle›

Trả lời: Với var, tất cả callback chia sẻ cùng một biến i; khi timeout chạy (sau khi vòng lặp kết thúc) thì i đã đạt giá trị cuối. Dùng let tạo binding mới mỗi vòng, hoặc bọc trong IIFE để "đóng băng" giá trị tại thời điểm đó.

Q9Phân biệt null và undefined. typeof trả về gì cho mỗi loại?Junior›

Trả lời: undefined nghĩa là biến đã khai báo nhưng chưa gán giá trị (mặc định của JS). null là giá trị cố ý gán để biểu thị "không có gì". typeof undefined === 'undefined', còn typeof null === 'object' (một lỗi lịch sử của JS). Chúng bằng nhau với == (null == undefined là true) nhưng khác nhau với ===.

Q10Shallow copy vs deep copy? Liệt kê các cách clone object và hạn chế.Middle›

Trả lời: Shallow copy chỉ sao chép cấp một; các object lồng bên trong vẫn dùng chung tham chiếu — dùng {...obj}, Object.assign({}, obj), arr.slice(). Deep copy sao chép toàn bộ cây — dùng structuredClone(obj) (hiện đại, giữ Date/Map/Set), hoặc JSON.parse(JSON.stringify(obj)) (mất undefined/Date/hàm, lỗi với vòng lặp tham chiếu), hoặc thư viện như lodash cloneDeep.

⚠️ Bẫy: nhiều bug do "tưởng đã copy" nhưng thực ra shallow → sửa bản sao vô tình sửa object lồng của bản gốc (xem lại phần primitive vs reference).
