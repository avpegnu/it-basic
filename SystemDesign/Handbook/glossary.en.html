  • Bind guarantees to scope and assumptions: consumer deduplication does not guarantee nonrepeated payments.

Timeout / cancellation

  • Stopping the wait does not prove remote work never ran; retries need identity and deduplication.

  • Leases bound rights in time; resource-side fencing rejects stale owners at effects.

  • An SLI is a measurement, an SLO a target and an SLA an agreement.

  • Requests per second are flow; active requests are occupancy, related through timing under suitable assumptions.

7. Always read units and boundaries

Check a number before using it

  1. Boundary

    Client, gateway, shard or fleet?

  2. Unit / population

    Requests, operations, tokens or bytes; are failures included?

  3. Window / statistic

    Mean, percentile or peak; rolling or fixed window?

  4. Assumptions

    Are retries, skew, correlation and headroom included?

A neat number without scope can mislead design.

Compare measurements only with compatible units and boundaries. Decimal MB differs from binary MiB, bits differ from bytes, and operation counts differ from operation rates. One logical request can generate multiple downstream operations.

Little's Law uses averages over a consistent stable system boundary and population. Substituting p99 does not yield an exact concurrency requirement. Request-based availability likewise does not directly translate into downtime minutes.

10. Interview drill: explain without buzzwords

Answer with a definition, example and boundary or failure; state uncertain assumptions and how to verify them.

Does TTL guarantee a fresh cache?

No. Entries can be stale before expiry, and delayed fills can republish old versions. Define allowed staleness, invalidation ordering and current authorization.

Does serializable mean everyone always sees the latest write?

No. Serializability concerns serial-equivalent committed transactions. Real-time transaction ordering requires an appropriate additional property such as strict serializability; read modes and actual engine semantics matter.

Can similarly named caches share keys based only on prompt text?

Not from their names. KV, prefix and response caches hold different artifacts and require compatible model, context, policy and freshness identities.

Does a good definition need product names?

No. Define behavior and guarantees first, then use a qualified implementation example. Naming a queue product does not specify its delivery, acknowledgement, retention or effect semantics.
