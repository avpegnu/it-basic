Thiết kế LLM Inference Platform: scheduling, streams và usage

Nối GPU memory, iteration scheduling, prefix routing và token escrow với TTFT/ITL, cancellation, metering và unit economics ở SLO đã nêu.

Một generation có nhiều resource contracts

  1. Admit

    Validate/count, reserve quota và bound queues.

  2. Place / execute

    Warm compatibility, hard KV allocation, prefill/decode.

  3. Stream và cancellation

    Bound buffers, explicit attempts và terminal outcomes.

  4. Meter / reconcile

    Authoritative usage, identity và safe release.

Giữ latency, memory và accounting cùng đúng.

  • Goodput tại latency/quality target khác raw token throughput.
  • Paged KV/prefix reuse vẫn cần per-rank memory, compatible identities và hard allocator.
  • Continuous batching tiết kiệm idle slots nhưng batch/context thay execution cost.
  • Streaming/cancel/retry giữ explicit attempt ownership và partial-output semantics.
  • Queue rejects rollback reservations; final usage settle có durable dedup/reconciliation.

1. Inference platform là lifecycle, không chỉ GPU endpoint

User latency

  • TTFT, inter-token gaps và terminal failures theo tier.

GPU resources

  • Compute, bandwidth, per-rank HBM và topology.

Request lifecycle

  • Admission, attempt ownership, cancel và final usage.

Bài này thiết kế hosted generation API với streaming, nhiều model/adapter revisions, interactive/batch tiers, quotas và usage metering. Training, RAG/tool orchestration và model quality research là scope riêng; request vẫn cần security/safety hooks theo product. AI Inference Fundamentals giải thích computation/memory cơ bản; case này nối gateway, scheduler, KV ownership, streams và final accounting thành một service có failure contract.

Tối ưu cost per useful output ở latency/quality target, không tối đa raw tokens/s bất chấp user bị timeout. Chốt model shapes, context distribution, input/output tails, concurrency, regions, availability và maximum queue delay. Một request có 10 tokens và request có 100K tokens không cùng cost; limit chỉ bằng requests/s bỏ qua token work, KV residency và output fan-out.

2. Tách input capacity, decode capacity và occupancy

Giả định 50M requests/day, average 1.000 input +300 output tokens, peak 3× average. Rate trung bình≈579 requests/s, output≈173,6K tokens/s và input≈578,7K tokens/s; peak≈1.736 requests/s,521K output và 1,736M input tokens/s. Những con số là scenario sizing, không traffic đo được. Prefill và decode có resource curves khác nhau; cached input giảm một phần prefill compute nhưng không tự giảm logical input counts hay xóa decode cost.

Nếu một benchmark giả định tại đúng SLO/mix cho 2.500 output tokens/s trên decode replica 8 GPUs, peak decode lower bound là ceil(520.833/2.500)=209 replicas,1.672 GPUs trước headroom. Không dùng số này làm whole-fleet count: thêm prefill capacity, redundancy, warm capacity, skew và actual goodput. Little’s Law dùng stable average arrival×mean in-system duration; nếu 579/s và 12s giả định thì≈6.944 requests trong system, không đồng nghĩa tất cả giữ KV vì queue/admission chưa vào GPU.

3. Request, attempt và stream event không cùng identity

API dưới đây là teaching contract, không tuyên bố wire compatibility của một provider. Request ID giữ user intent/pinned model parameters; attempt ID giữ execution lease/generation; event sequence phục vụ stream delivery nếu platform thật hỗ trợ resume. Chỉ set idempotency header không tự tái tạo KV, sampling state hoặc missed tokens. SSE là response stream của HTTP request; event/chunk có thể chứa nhiều tokens, metadata hoặc terminal status, không mặc định một event=một token.

Before headers, quota/validation/admission errors dùng HTTP contract rõ. Sau stream start, HTTP status không thể đổi như một response mới; dùng typed terminal/error event nếu connection còn sống và persist server outcome. Client disconnect không bảo đảm thấy final usage. Resume phải có durable retained events/cursor và compatible execution state theo policy; nếu không hỗ trợ thì báo interrupted partial generation và explicit retry action, không nối âm thầm câu trả lời mới.

          4. Một front door quen thuộc, resource ownership khác

          Gateway authenticate/validate stream; admission reserve quota và bounded queue; scheduler chọn warm eligible replica rồi allocator enforce hard capacity. Colocated replica thực hiện prefill/decode và quản KV state; prefix cache có compatibility/isolation keys. Registry pin weights/tokenizer/template/adapters. Usage log và settlement độc lập với client stream để retries/disconnect không làm mất accounting. Đừng đặt mọi queue trong unbounded gateway RAM.

          Scheduler observations có thể stale; free KV hint không phải allocation guarantee. Worker/allocator phải atomically reserve hoặc preempt/reject trước actual execution; retries giữ request/attempt identity và cleanup ownership. Queue limit cần bound estimated tokens/work/deadlines ngoài request count, vì một long context có thể chiếm nhiều tài nguyên. Per-tier fairness cần tránh batch starvation hoặc interactive bị batch chiếm hết.

          Từ admitted request tới final usage

          Sơ đồ các component; các luồng request được giải thích đầy đủ theo thứ tự bên dưới.

          Generate và stream

          1. Gửi pinned model intent, max output và stable request identity.
          2. Validate context/tokenizer, reserve quota và establish admission decision.
          3. Enqueue có bound; reject trước worker start thì refund theo reservation ID.
          4. Select eligible warm replica theo deadline/work/KV evidence.
          5. Atomic capacity admission rồi prefill prompt/suffix.
          6. Same-replica handoff hoặc explicit compatible KV transfer.
          7. Sequenced deltas có thể chứa nhiều tokens/chunk; bounded buffers.
          8. Render partial output, finish/error/cancel state rõ.

          Prefix hit có điều kiện

          1. Request prefix signature và scope được xét cùng load.
          2. Match effective tokens/model/adapter/KV/position config và tenant scope.
          3. Pin reusable pages; chỉ prefill suffix không cached.
          4. Decode vẫn tạo output mới và cần KV growth.

          Disconnect và cancel

          1. Connection mất hoặc client gửi cancel; outcome chưa tự terminal.
          2. Signal current attempt cancellation; worker kiểm boundary an toàn.
          3. Publish terminal outcome và authoritative counters sau stop/finalize.
          4. Dedup terminal event rồi settle used/refund; unknown cần reconcile.

          Final usage dù client đã rời

          1. Record input/cached/generated counts, pinned versions và termination status.
          2. Apply identified final usage/settlement một lần; retry không double charge/refund.
          3. Release remaining reservation theo policy; rate-limit refill là contract khác.

          Warm model rồi nhận traffic

          1. Publish compatible revision/config và eligibility metadata.
          2. Load/verify weights, tokenizer/template và kernels; readiness sau warm checks.
          3. Warm pinned version; drain streams cũ, không mix incompatible KV.
          App / SDK
          Request identity, stream event cursor nếu protocol hỗ trợ, partial output và cancellation state.
          Gateway / stream
          Authenticate, validate limits, hold response stream; disconnect chuyển thành cancel/reconciliation.
          Quota / admission
          Atomic token reservation và tier queue bounds; rejection phải rollback reservation.
          Tier / model queues
          Deadlines, fairness và bounded token work; batch không làm interactive starvation.
          GPU-aware scheduler
          Warm model/adapter compatibility, queue/estimated work, hard KV admission và bounded prefix affinity.
          Prefill execution
          Tokenize/encode và build compatible prompt KV; chunking/transfer là workload-dependent choices.
          Decode execution
          Iteration-level scheduling, token generation, output counters và cooperative cancellation.
          Paged KV / prefix
          Per-rank blocks, pinned references, exact compatibility keys và tenant isolation.
          Model / adapter registry
          Immutable versions, tokenizer/chat template, formats/kernels và verified warm readiness.
          Terminal usage log
          Durable authoritative usage, status, attempt IDs và dedup/reconciliation; không phụ thuộc client đọc final event.
          Usage settlement
          Settle reservation đúng một lần theo identity/policy, audit counts và refunds.

          5. TTFT, inter-token latency và goodput đo những gì?

          Before first output

          • Queue age, tokenization/prefill/transfer và proxy flush.

          During generation

          • ITL tails, batch changes, KV reads và backpressure.

          Outcome

          • Completion/cancel/error counts cùng SLO denominator.

          TTFT ở client boundary gồm network, auth/tokenization/admission, queue, prefill/transfer và first generation/flush tùy implementation. Prefill completion không luôn trùng first visible chunk. ITL là các gaps giữa output events/tokens theo measurement rule; TPOT trung bình sau first token có thể định nghĩa là (thời điểm token cuối − thời điểm token đầu)/(số output tokens −1) khi có ít nhất 2 tokens, nhưng không thay p95/p99 gap distribution. Chunk buffering ở proxy cũng có thể tạo burst dù engine đều. Track denominators và one-token outputs riêng.

          Prefill thường compute-heavy khi prompt/batch phù hợp; small-batch decode thường nặng weight/KV bandwidth. Long context, big batch, attention variants, parallel communication và multimodal encoders thay bottleneck; không dùng hai nhãn này như định luật. Goodput là useful throughput thỏa latency/quality/termination criteria đã chọn. Đếm chỉ completed requests và bỏ timeout/cancel có thể làm dashboard đẹp giả trong overload.

          6. Continuous batching tái dùng slots, không tạo free compute

          Static group có thể giữ capacity cho đến khi whole group finish; short request vẫn có thể được stream/return sớm. Iteration-level scheduling cho sequences rời/vào tại iteration boundaries, giảm idle slots trong heterogeneous output lengths. Real engines vẫn có batch/token budgets, allocator và prefill scheduling; thêm sequences tăng attention/compute/KV traffic nên “32 sequences cost như 1” chỉ là intuition weight reuse ở một số regimes, không performance law.

          Mô phỏng dưới chỉ giữ mỗi active sequence một token/tick để thấy occupancy, không dự đoán GPU speedup. So sánh đúng token work, arrival và short-response finish times trước khi suy luận efficiency. Batch tăng có thể nâng throughput nhưng xấu ITL/TTFT; tối ưu ở SLO chứ không chỉ occupancy 100%.

          7. HBM capacity phải đúng shape và đúng từng rank

          Full-attention KV payload/token =2 ×layers ×KV heads ×head dimension ×bytes, với factor 2 cho K/V; dùng KV heads của GQA/MQA thay query heads. Ví dụ shape 80 layers,8 KV heads,128 dim,2-byte KV:327.680B=320KiB/token;1.300 tokens≈426MB≈406,25MiB per sequence trước pages/metadata. Đây là shape giả định, không gán mọi 70B model cùng configuration. Sliding windows, MLA/compressed state, cross-attention và multimodal state cần formula riêng.

          Weights70B ×2B =140GB không chứng minh 2 × 80GB đủ chạy: runtime/graphs/activations/workspace, KV, allocator/padding, communication buffers và safety headroom còn thiếu. Aggregate HBM không cứu một rank OOM. TP có thể shard KV heads nhưng KV replication/padding và parallel plan ảnh hưởng actual per-rank memory; phải validate layout. Weight quantization không tự quantize KV; capacity gain/quality/kernel support cần eval, không mặc định tổngcapacity 2×.

          Paged allocation giảm một số fragmentation và hỗ trợ sharing nhưng cần block tables, pinned references và safe release. Allocate maximum whole context bảo thủ có thể giảm utilization; incremental allocation cần growth/headroom/preemption policy. KV exhaustion có thể queue, preempt/recompute hoặc offload theo engine; không giả mọi engine luôn swap được hoặc recompute miễn phí. Cancel xác nhận xong mới release KV ownership ở safe boundary.

          8. Prefix affinity phải có load bound và isolation

          Cache reuse cần exact effective token prefix và compatible model revision, adapter, positional/attention configuration, KV representation cùng namespace isolation. Same text có thể tokenize khác vì template/version; semantic similarity không đủ. Prefix pages đã cache vẫn chiếm memory; active sequences pin shared pages và private suffix pages. Cache hit giảm eligible prefill work, không trả cached answer, không tránh decoding output và không tự cấp quota discount.

          Affinity không thắng mọi queue: route tới cache-hot replica bị backlog lớn có thể xấu TTFT hơn cold replica rảnh. Scheduler cần warm compatibility, estimated queue/token work, free KV và deadline/tier. Observed headroom phải được allocator xác nhận atomic. Lab dùng work units không phải latency oracle; production cần workload-calibrated prediction và fairness để không giấu long prompts trong queue count nhỏ.

          9. Chunk prefill hay tách pools theo evidence

          KV handoff có ownership

          1. Prepare

            Target reserve blocks và xác minh layout/version.

          2. Transfer

            Copy/check data dưới attempt identity.

          3. Accept

            Target confirm usable state, source release theo protocol.

          4. Recover

            Timeout/cancel reconcile current owner và reclaim an toàn.

          Không release nguồn khi target chưa nhận responsibility.

          Long unchunked prefill trong mixed replica có thể delay decode iterations. Chunked prefill giới hạn prompt work mỗi scheduling round để cân TTFT với ITL, nhưng chunk size/budget/kernel overhead vẫn workload-dependent. Tách prefill/decode pools giảm interference và cho independent sizing/parallelism, nhưng thêm queue, allocation handoff và KV transfer. Không mặc định prefill “một pass cả prompt” luôn là actual scheduler behavior.

          Ví dụ KV 320KiB/token ×8.192 prompt tokens=2,5 GiB. Link hiệu dụng 50GB/s thập phân có serialization lower bound≈53,7ms cho payload đó, chưa contention/latency/serialization/layout conversion; không lấy tốc độ NIC nominal làm throughput end-to-end. Transfer cần version/layout compatibility, ownership, pin/release và cancellation/error cleanup. So sánh SLO goodput và total cost với colocated/chunked baseline trước rollout.

          10. Reservation, usage và rate-limit refill là contracts khác

          Validate prompt/context/output cap và count bằng pinned tokenizer; reserve bounded input+max output hoặc equivalent cost budget theo tenant/tier. Queue insertion reject phải rollback đúng reservation ID—không chỉ return 503 sau đã trừ tokens. Fixed spending budget, TPM rate limiter và billable monetary ledger có semantics khác; refill/refund không dùng một công thức chung cho mọi bucket. Cache discounts và reasoning/hidden/generated token categories cũng cần explicit product policy.

          Final usage đến từ trusted execution counters và request/attempt identity, gồm completed, cancelled và failed attempts theo policy. Mới cancel requested chưa đủ giải phóng reservation vì worker có thể đang compute. Terminal event phải durable, dedup và reconcile khi worker/gateway crash; client không nhận usage chunk không làm server quên charge/refund. Corrections nếu có cần version/monotonic policy, không last-arrival overwrite arbitrary cumulative counts.

          11. Streaming retry không chỉ phụ thuộc first token

          Trước first visible output, old attempt vẫn có thể được admitted/running hoặc đã compute output trong buffer. Blind failover có thể chạy hai generations và double bill. Dùng attempt lease/fencing hoặc provider execution contract để xác nhận chưa accepted, đã cancel/stopped hay reconcile retained result. Sau partial output không silent restart rồi ghép response khác; explicit retry tạo attempt mới phải có UI/output/accounting semantics. Same seed cũng không tự bảo đảm bitwise same output khi engine/config/hardware thay đổi.

          Disconnect detection và cancel delivery có delay; some kernels không interrupt ngay. Stop tại safe scheduler boundary, record final counts, release KV và unused reservation theo owner. Worker loss có thể mất volatile KV/sampling state nên generic stream resume không available; log enough replay/output evidence nếu product hứa resume. Slow consumers cần bounded gateway buffers và policy cancel/spool/backpressure, không để một mobile client giữ GPU/KV vô hạn.

          12. Version model, adapter và execution configuration cùng nhau

          Registry pin weights, tokenizer/chat template, adapter/base compatibility, quantization, kernels và context/attention config. Readiness cần load/verify/warm, không chỉ pod started. Rollout canary quality/latency, keep old streams pinned và drain trước unload; cache key generations phải tránh reuse incompatible KV. Cold-start duration đo theo image/weight distribution, host cache, allocation và warmup, không assume mọi model mất đúng vài phút.

          Data parallel replicas thêm throughput; tensor/pipeline/expert/context strategies thay per-rank memory và communication. Không chọn GPU count chỉ bằng weights/80GB. Nhiều LoRA adapters có thể share compatible base với supported kernels/registry/cache; full fine-tunes đổi base weights không tự share cùng payload. Adapter affinity và eviction cũng cần tenant fairness; không hứa mọi adapter/kernel batch chung mà không test support.

          13. Cost per million tokens phải đi cùng SLO và phạm vi cost

          Giả định giả lập 8 GPUs ×$3/GPU-hour=$24/hour và decode goodput 2.500 output tokens/s=9M/hour, decode-GPU-only cost≈$2,67/M output tokens ở sustained full goodput. Nếu actual useful throughput bằng 50% thì≈$5,33/M với cost không đổi. Đây không phải price hiện hành hay tổng serving price: prefill, CPU, network, storage, idle/warm replicas, redundancy và failed attempts chưa gồm. Không so engines bằng unit cost nếu quality/context/SLO hoặc workload khác.

          Prefix reuse, quantization, speculative decoding và batching tác động các phần khác nhau. Speculation thêm draft/verification work và acceptance-rate dependence; không chắc thắng ở high batch hoặc workload khó dự đoán. Quantization có numerical/kernel/quality trade-offs không chỉ memory ratio. Batch/offline tiers có thể dùng cheaper flexible capacity theo deadline nhưng region/spot interruptions cần recovery/cost controls; interactive không tự phù hợp.

          14. Warm capacity, fairness và safety budgets

          Autoscale theo queued token work/age, KV pressure, SLO goodput, preemptions và per-model/tier skew; CPU% hoặc GPU utilization một mình không đủ, nhưng không phải hoàn toàn vô ích cho diagnosis. Keep measured warm headroom, prefetch model assets và smooth traffic; node provisioning/model warmup có delay nên reactive scale không chữa instant burst. Admission shed/retry-after ở known nonacceptance boundary bảo vệ SLO thay vì unbounded queue.

          Tenant token/cost budgets chống denial-of-wallet, đồng thời bound context/output, parallel requests, adapters, prefix namespaces và retained outputs. Treat model artifacts/adapters như untrusted supply-chain inputs theo chosen format/runtime controls. Safety/classification stages có latency/throughput/cancel policy riêng; output moderation có thể cần buffering làm tăng TTFT/ITL. Không để prompts/keys/stream content lộ trong logs; cache isolation và data retention là service requirements chứ không chỉ optimization flags.

          15. Data model và failure evidence

          Request record giữ tenant/request ID, pinned input/model intent hash, status và attempt history; attempt record giữ worker ownership, epoch/cancellation state, admission/reservation reference và terminal usage identity. Usage events gồm counter definitions, model/adapter/tokenizer revisions, input/cached/generated counts, outcome và settlement version. Replica status là observation có timestamp/epoch; scheduler không dùng một stale kvFreeBlocks như lock. Persistent ledger không nhất thiết nằm trên per-token streaming hot path nhưng final outcomes không được chỉ best-effort fire-and-forget.

          Drill gateway chết sau reserve, queue reject, worker chết mid-stream, client chậm/disconnect, duplicate terminal event và replica model rollout. Check quota conservation, no double settlement, no live KV early release, version-compatible cache, bounded queues và client-visible partial status. Plot latency distributions gồm failures/cancels và time-series per replica để tìm affinity hot spots; average fleet GPU utilization có thể che skew.

          16. Luyện thiết kế ở latency và failure boundaries

          Vẽ request có long prompt, prefix hit trên hot replica, client disconnect sau partial output và terminal event bị gửi hai lần. Nêu mỗi stage giữ quota/KV gì, worker nào còn authority và client biết outcome tới đâu. Chỉ ra phép đo nào cần trước khi tăng batch hoặc tách pools.

          TPOT mean tốt có chứng minh stream mượt không?

          Không. ITL tails, proxy chunk buffering, stalls và cancelled/failed requests có thể bị mean che. Định nghĩa token/event boundaries và denominator; one-token responses không có cùng TPOT formula.

          Cache hit nhiều mà TTFT xấu thì sao?

          Affinity có thể tạo queue skew; prefix chỉ giảm eligible prefill. Kiểm per-replica work/age, compatibility và hard KV allocator; cold replica rảnh có thể finish nhanh hơn cache-hot replica backlog.

          Reserve quota rồi queue reject cần làm gì?

          Rollback reservation bằng stable identity, đúng một lần. Không bỏ qua refund vì return 503; tách fixed budget, TPM limiter và monetary settlement semantics.

          Client disconnect có refund hết ngay không?

          Không nếu worker còn active/unknown. Signal cancel, confirm terminal counts, settle actual used và release remainder theo policy. Client-visible tokens không chắc bằng generated counters.

          Chưa first token có được blind fallback model không?

          Không tự động: old attempt có thể running hoặc output đang buffer. Cần known nonacceptance, stopped/fenced attempt hoặc execution dedup/reconciliation. Partial outputs cần explicit restart/resume policy.

          140GB weights có đủ chọn 2 × 80GB không?

          Chưa. Cần per-rank runtime/workspace/KV/graphs/communication/headroom và topology/kernel plan. Aggregate fit và bytes/parameter không chứng minh execution fit hay SLO.

          Disaggregate luôn tốt hơn colocated không?

          Không. Nó giảm interference/cho independent sizing nhưng KV transfer, network topology, target allocation và failures thêm cost. So với chunked colocated baseline bằng same workload/quality/SLO goodput và total cost.

          Final usage qua message broker có tự exactly-once bill không?

          Không. Durable event/outcome và sink dedup/settlement identity/version phải phối hợp. Duplicate event, lost reply, corrections và cancellation có recovery policy; budget balance đẹp không chứng minh actual charge đúng.
