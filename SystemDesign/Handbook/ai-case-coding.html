Coding Assistant: snapshots, context và patch có evidence

Tách inline completion khỏi chat/agent; thiết kế request validity/cancellation, FIM/context packing, repo overlays, scoped prefix cache, isolated execution và patch apply. Đánh giá correctness cùng acceptance/retention, latency và privacy.

Từ editor snapshot đến reviewable result

  1. Capture / scope

    Document version, caret/ranges, org/repo policy.

  2. Select context

    Allowed current evidence trong actual token budget.

  3. Generate

    Bound request profile, streaming và cancellation.

  4. Validate / test

    Snapshot validity hoặc isolated patch checks.

  5. Show / apply

    Current preconditions, review policy và outcome evidence.

Không coi generated text là edit được phép apply lên bất kỳ workspace nào.

  • Inline completion và chat/agent có latency/interaction budgets khác nhau; cả hai vẫn cần correctness, privacy và bounded work.
  • Debounce/cancel không thay document/range/request validity checks cho late responses.
  • Context budget phải tính cả required content/format overhead; exclusions áp trước collect/store/send theo policy.
  • Prefix reuse cần exact compatible identity và capacity; sticky routing/small models/speculation không có universal speedup.
  • Patch phải bind current base, tested artifact/environment và required review policy; apply không blind overwrite concurrent edits.
  • Accepted/retained code là product signals, không ground truth correctness/security hay causal productivity.

1. Hai interaction paths, cùng product boundaries

Inline completion

  • Short usefulness window, snapshot/caret validity và cancellation.
  • Bounded output; editor vẫn responsive khi unavailable.

Chat / agent

  • Repo understanding hoặc multi-file task với explicit goal.
  • Bounded search/edit/test và concrete artifact evidence.

Shared constraints

  • Code privacy, permissions, exclusions và approved routes.
  • Correctness/security/quality cùng latency và cost.

Inline completion tạo ghost text/suggestion gắn với current cursor; chat giúp hiểu codebase hoặc đề xuất edits; agent có thể search/edit/build/test trong allowed scope. Inline cần hữu ích khi developer còn chờ, còn agent task có thể dài hơn nhưng phải bounded và reviewable. Không biến “nhanh” thành lý do bỏ quality/security, hoặc coi mọi response tới sau một ngưỡng chung đều vô dụng cho mọi task.

Requirements gồm allowed languages/editors/repos, completion/chat/task APIs, excluded content, approved model/data endpoints, execution permissions và degradation khi service down. Normal editing không được block vào model dependency. Training/retention/residency options là product policies cần enforce và verify ở connectors/providers/storage, không chỉ lời hứa trên UI.

2. Capacity planning: requests khác useful suggestions

Planning fixture: 100000 active developers, 150 admitted completion requests/ngày sau debounce, peak bằng 4× average. Mỗi admitted completion giả định 1500 input +24 output tokens. Chat/agent có 6 turns/developer/ngày, mỗi turn 7800 input +200 output. Đây là explicit hypothetical workload, không throughput hoặc price benchmark.

15M completions/ngày≈173,61 average QPS và 694,44 peak. Prompt volume lớn không tự chứng minh prefill dominates billed cost hoặc GPU occupancy: cached-input rates, context lengths, batching, output length, hardware và task mix đều quan trọng. Canceled requests vẫn có thể đã tiêu work/bill; capacity model cần measured arrival/service/cancellation distributions và headroom.

3. APIs phải mang snapshot và artifact identity

Completion response cần request/document/caret generation metadata để client loại stale proposal. Chat references và agent task bind workspace/base revisions; principal/repo authorization lấy từ trusted session, không model-picked repo ID. Event telemetry phải phân biệt generated, shown, accepted, dismissed, obsolete và canceled theo definitions nhất quán.

        4. Completion path và agent path tách compute/control

        IDE/local context service sở hữu current buffers/ranges và exclusion policy. Gateway chọn approved route với capacity/data constraints; completion service optimize short requests, chat/agent orchestrates longer bounded tasks. Repo index giữ revisions/staleness; isolated runner tạo tested artifacts, còn apply gate kiểm workspace hiện tại. Không cần một large model hoặc one-size timeout cho cả hai paths.

        Inline suggestions và agent patches có validity boundaries khác nhau

        Sơ đồ các component; các luồng request được giải thích đầy đủ theo thứ tự bên dưới.

        Trace inline request, repository context, stale-response cancellation, sandbox edits hoặc patch apply. Model output chỉ là proposal cho một document/workspace snapshot cụ thể.

        Inline completion theo snapshot

        1. Debounce typing và capture current document/caret snapshot.
        2. Filter excluded/sensitive context trước network; bind request generation.
        3. Admit bounded task/region/model profile.
        4. Use compatible FIM prompt và bounded generation.
        5. Show only valid current-snapshot suggestion theo usefulness deadline.

        Context có local overlay

        1. Resolve open/recent buffers và current symbols.
        2. Retrieve scoped snippets với commit/buffer revision metadata.
        3. Apply unsaved overlay/freshness rules, dedup và token budget.
        4. Pack permitted compatible evidence, không block editor chờ optional slow context.

        Superseded requests và late responses

        1. Cancel prior request khi snapshot đổi; tag newer generation.
        2. Propagate supported cancellation, không assume mọi compute đã stop.
        3. Late replies vẫn phải check document/range/request validity.
        4. Record shown vs obsolete/cancelled/late bằng denominators riêng.

        Agent edits trong isolated workspace

        1. Bind authorized goal và immutable workspace/base revision.
        2. Search relevant current context, treat repo text là data.
        3. Apply proposed edits/build/tests dưới tool/resource policy.
        4. Record exact patch/base/environment và test outcomes/limitations.

        Review và apply đúng artifact

        1. Present concrete diff, checks, scope và unresolved risks.
        2. Authorize theo current user/product review policy, bind exact payload.
        3. Verify base/test/review identity và current commit preconditions.
        4. Apply under supported atomic/conflict contract; không overwrite user edits blind.
        5. Record task outcome/cost và review result theo privacy policy.
        IDE
        Current buffers, document versions, caret/ranges, exclusions và review UI.
        Local context
        Prefix/suffix, symbols, unsaved overlays và permission-aware context selection.
        Gateway
        Trusted org/repo identity, approved endpoints, budgets và request generations.
        Completion

        Repo index

        Patch evidence

        Apply gate

        5. Document versions, superseded requests và late replies

        Debounce giảm request count khi typing liên tục, nhưng thêm delay vào useful window. Khi document/caret đổi, invalidate prior proposals và request cancel theo supported contract. Response tới muộn vẫn phải match request epoch, document version/content, replace range và relevant prefix/suffix preconditions; một completion hợp lệ cho v7 không tự hợp lệ cho v8 chỉ vì cùng file path.

        Versioned editor/LSP contracts giúp kiểm document state; position encoding và range semantics phải theo client protocol, không tự coi byte offset là character position. Cancel có thể chưa propagate hoặc provider vẫn hoàn thành work; drop stale replies ở client/server là correctness boundary riêng với resource savings. Undo/redo, tab changes, branch switch và unsaved overlays cũng cần test.

        6. Đo latency budget theo actual critical path

        Optimize theo measured bottleneck

        1. Capture

          Debounce/context extraction và allowed snapshot.

        2. Admit

          Queue/concurrency, deadline và cache locality.

        3. Generate

          Compatible profile, prefill/decode và output bounds.

        4. Render / discard

          Show useful current proposal hoặc drop stale/late.

        Mỗi optimization cần latency và task-quality evidence.

        Break down debounce, local context, network, queue/admission, prefill, decode, response buffering và render. Một số stages parallel/optional nên không luôn cộng mọi duration; end-to-end tail không bằng tổng p95 của từng stage. Measure time-to-useful-suggestion và rate hợp lệ còn trong pause window theo language/task/device, cùng correctness và acceptance signals.

        Model nhỏ/FIM-specialized, prefix reuse, speculative decoding, regional routing và short outputs có thể giúp under measured conditions. Không có fixed “nhỏ hơn nhanh X lần” hoặc speculation speedup constant cho mọi batch/hardware/acceptance. Sticky routing cần balance cache locality với saturation/hotspots/failover, và approved residency có thể giới hạn region choice. Optional repo context miss deadline thì skip/degrade rõ thay block editor.

        7. FIM và bounded context assembly

        Fill-in-the-middle conditioning dùng code trước/sau insertion point để generate middle theo model/template hỗ trợ; special tokens/order không universal giữa models. Include necessary local prefix/suffix, relevant definitions/types/tests và suitable repo snippets theo actual token budget. Larger context không tự better quality; stale/irrelevant hoặc malicious context có thể làm tệ hơn. Local data tránh một network lookup nhưng vẫn có CPU/extraction/privacy và input-token costs.

        Count required pieces, templates, tool schemas và reserved output/context headroom. Nếu required content vượt budget, shrink/reframe/decline theo policy hoặc alternate mode, không use required=true để bypass limit. Enforce exclusions trước collection/storage/indexing/embedding/network theo scope; server-side policy cũng cần kiểm nhưng không thể undo secret đã gửi.

        Required prefix/suffix cần 600 tokens; optional greedy order là excluded config, type definition, relevant test, README. Ở budget 1500/exclusions ON, test 500 không còn fit sau type 600 nên README 300 được chọn. Không có claim README hữu ích hơn test hoặc greedy packing tối ưu; priorities/counts là fixed inputs. Production tính thêm actual tokenizer/template/output headroom trước dùng remaining input budget.

        8. Repo retrieval phải hiểu commits và unsaved overlays

        Index code theo repository/branch/commit generation, file content hashes và parser/symbol/embedding profiles. Definitions/references giúp context nhưng language server có capabilities, update lag và parse errors khi code đang gõ dở. Combine lexical/symbol/semantic retrieval theo evals thay assume vector search đủ mọi exact API name hoặc dependency version.

        Current open buffer có thể mới hơn disk/index; overlay local edits và mark stale snippets để không mix inconsistent workspace assumptions. Rewrites, generated files, symlinks/path canonicalization, branch changes và excluded paths cần policy. Không đem unrestricted repo-wide snippets tới model chỉ vì index trả similarity cao.

        9. Prefix/KV reuse và suggestion cache identity

        KV/prefix reuse phụ thuộc exact compatible token prefix, model/weights/tokenizer/template/attention settings, tenant/session isolation và residency. Changing suffix/context order hoặc model profile có thể đổi shareable prefix; sticky sessions chỉ giúp khi cache tồn tại và capacity tốt. Không reuse arbitrary similar code như identical KV state.

        Suggestion response cache cần bind document/range/prefix/suffix, model/settings, scope và policy versions; backspace/retype có thể hit khi preconditions thật sự match. Cache hit không bypass current document validity/exclusions. Track logical input, cache reads/writes, output tokens và actual provider usage để estimate cost; no universal prefill dominance chỉ từ prompt length.

        10. Agentic edits: task scope, bounded loop và evidence

        Một vòng edit có evidence

        1. Inspect / plan

          Goal, base, path/tool scope và relevant checks.

        2. Propose edits

          Concrete diff trong isolated snapshot.

        3. Verify

          Run tests/checks, record environment/artifact IDs.

        4. Review / apply

          Current preconditions, authority và conflict handling.

        Outcome là task behavior trên exact artifact, không chỉ model narrative.

        Bind goal và base/workspace snapshot, allow specific paths/tools và preserve user changes. Agent có thể inspect, propose edits và run relevant checks, nhưng stop conditions gồm completed goal, budgets, errors, blocked permissions và unresolved conflicts. “Loop tới khi tests xanh” không đủ: deleting tests hoặc changing expected output để che bug không là task success.

        Keep test/eval oracles và execution policies appropriately controlled; review production behavior, test modifications và diff scope. Tool results/repo comments/issues đều untrusted data, không cấp permission cho network/push/credential access. Policy có thể preauthorize reversible local edits trong requested scope và require concrete review cho risky/external steps; không cần tự phát tạo confirmation sau từng low-risk edit đã được delegate.

        11. Sandbox cho code và build/test scripts

        Repo build/tests/dependency install có thể execute arbitrary code, kể cả model không sinh một shell payload trực tiếp. Dùng isolated ephemeral workspace/VM/container phù hợp risk, không production credentials, bounded CPU/memory/time/process/filesystem và reviewed network/dependency policy. Container label không tự chứng minh isolation nếu mount host secrets hoặc privileged sockets.

        Dependencies có thể cần network; dùng approved mirrors/caches/allowance thay blanket assume mọi task build offline được. Network access vẫn cần destination/data rules và supply-chain review. Test artifacts/logs có thể leak code/secrets, nên minimize, scope và retain theo policy. Bounded execution failure phải return useful diagnostics thay retry/runaway install vô hạn.

        12. Test/review evidence phải bind exact patch và base

        Record base content/workspace revision, proposed patch hash, touched paths, test commands/results, environment/dependency versions và required review decision. Nếu patch hoặc base đổi sau tests/review, evidence có thể không còn áp dụng; rebase/retest/review theo risk thay carry forward green badge tự động. Tests passing chỉ bao phủ checks thực sự chạy, không proof mọi behavior đúng.

        Validate current state tại apply/commit boundary bằng supported compare-and-swap/conflict contract; precheck rồi user edit trước write là TOCTOU. Multi-file editor/workspace operations không luôn transaction như database; define atomicity, partial failure/rollback và conflict reporting theo client capabilities. Không blind overwrite user changes để “apply succeeded”.

        13. Offline evals: functional correctness, repo tasks và pass@k

        Function-level generated-code tests, typecheck/lint, security checks và repository-level issue tasks đo những scopes khác nhau. Use held-out recent/representative code có permission, languages/framework slices và controlled environments; inspect contamination, dependency drift và flaky tests. A suite pass không chứng minh code secure hoặc satisfies every product requirement.

        Pass@k đo xác suất/estimated success khi có budget k candidate samples và ít nhất một candidate qua defined tests; không là acceptance rate hoặc quality của first shown completion. Với n≥k samples và c passes, một estimator dùng 1−C(n−c,k)/C(n,k); ví dụ n=10,c=2,k=2 cho 17/45≈37,8%. Sampling assumptions và test coverage vẫn quan trọng; compare models với same harness, sampling/budget và uncertainty.

        14. Acceptance và retained code là signals, không ground truth

        Track generated→eligible→shown→accepted/dismissed→retained/reverted với clear denominators. Acceptance của shown suggestions bị selection bởi latency, suggestion length, UI và task difficulty; retained chars không chứng minh semantic correctness hoặc long-term productivity. User có thể accept insecure code hoặc later delete good code vì design đổi. Combine signals với task outcomes, review burden, security/regressions và developer research.

        Online experiments cần appropriate assignment unit, duration, guardrails và clustering theo developer/repo; workload/learning effects có thể bias naive comparisons. Measure latency tails/cancellation/cost với quality, không chỉ optimize acceptance của very short trivial snippets. Telemetry pseudonymous IDs vẫn có privacy implications; không gọi hash là automatic anonymization.

        15. Exclusions, data residency và policy propagation

        Org/user exclusion policy phải apply cho local extraction, LSP/context snippets, indexing/embeddings, remote generation, caches và diagnostics theo scope. Gitignore không tự là privacy policy; symlinks, case sensitivity, renamed files, pasted secrets và context from generated artifacts cần handling. Secret detection có false negatives/positives; least exposure và narrow permissions vẫn cần.

        Allowed endpoints/regions, training usage và retention phải phù hợp actual vendor/self-hosted contracts/configuration. Code content không cần được stored trong normal telemetry để count outcomes, nhưng metadata/path/timing cũng có thể sensitive. Data-policy changes cần propagate/invalidate caches/queued work phù hợp; server filtering không unsend prior client uploads.

        16. Graceful degradation giữ editor hoạt động

        Khi capacity hoặc latency xấu, có thể shorten output, skip optional remote context, route tới qualified profile hoặc pause completions; lựa chọn phải preserve policy/quality expectations và clear UI state. Agent tasks có thể queue bounded, checkpoint hoặc stop với report. Không áp một ladder universal nếu task nhỏ hơn context lại làm unsafe edits.

        Prioritize current requests và fair per-org/developer quotas; stale cancellation giúp nếu supported nhưng không nên giả định fixed queue saving. Session stickiness có fallback/load escape; autoscaling cần warmup/cache behavior và measured peak distributions. Product SLA nên gồm editor responsiveness và task quality, không chỉ model endpoint uptime.

        17. Artifact/telemetry data model và release controls

        Artifact manifest giữ proposal/base/patch/environment identities, commands/check outcomes, scope, dependency/model/profile revisions và authorized decision refs. Completion telemetry giữ request/document generation IDs, model/profile revision, timings, usage, shown/adoption state và scoped aggregate retention metrics; raw source absent by default không tự làm metadata public.

        Model/template/context/index changes cần offline correctness/security/repo suites, latency/load checks và controlled online rollout. Review end-to-end effects của context exclusions, suffix processing, stale proposals và patch apply races. Keep rollback compatible profiles và retain enough minimized evidence để diagnosis, không chỉ model version string.

        18. Luyện giải thích Coding Assistant

        Giữ completion nhanh ở peak bằng cách nào?

        Đo critical path và time-to-useful-current-suggestion theo workload, bound queue/output/context, debounce và cancel supported work. Evaluate FIM/model/cache/locality choices cùng quality/privacy; skip optional context hoặc pause khi cần. Không hứa speedup fixed chỉ từ parameter count.

        R1 về sau R3 nhưng cùng file, có show được không?

        Không nếu document/range/request snapshot không còn match. Cancel không bảo đảm response biến mất; current version/content/preconditions gate phải drop obsolete result. Check undo/redo/tab/caret/branch scenarios.

        Required prefix/suffix quá budget thì sao?

        Không tự vượt limit bằng required=true. Count template/schema/output headroom, shrink/reframe theo policy hoặc alternate mode/decline. Required context và exclusion policies đều là constraints, không override nhau bằng model claim.

        Tests đã xanh nhưng user đổi workspace trước apply?

        Bind evidence với exact base/patch/environment và validate current version tại commit boundary. Nếu conflict, report/rebase/requalify phù hợp; không overwrite user edits để force success. Multi-file atomicity phải theo supported client contract.

        Model acceptance tăng có chắc tốt hơn không?

        Không: shown-selection, latency, length/UI và task mix có thể đổi. Acceptance/retention là signals, combine với correctness/security, task outcomes, review burden và suitable controlled experiments.

        Sticky routing có luôn giữ được prefix cache không?

        Không khi cache evicted, model/profile/token-prefix đổi, replica unhealthy hoặc locality gây queue hotspot. Scope exact compatible identity, monitor hits/latency/cost và có load escape/rollback.

        Agent chạy tests trên laptop có đủ sandbox không?

        Không tự đủ: repo scripts/dependencies là executable code và có thể truy cập host secrets/network. Dùng appropriate isolated workspace/resources/credentials và controlled dependency/network policy; container cũng cần review privileges/mounts.

        Pass@k cao có nghĩa first suggestion tốt không?

        Không: k-candidate test success khác first shown/accepted outcome và có budget/harness/test coverage assumptions. Compare matched sampling và evaluate product latency/adoption/correctness riêng.
