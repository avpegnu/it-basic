LLM Gateway: routing có policy, streaming và usage đáng tin cậy

Thiết kế shared AI data plane: aliases/capability contracts, qualified routing, replay boundaries, hierarchical quotas, atomic reservations, per-attempt usage/cost, scoped caches/logs và multi-region recovery.

Từ contract tới usage evidence

  1. Authorize

    Trusted identity, entitlement và data classification.

  2. Reserve / route

    Atomic exposure hold và qualified target.

  3. Attempt / stream

    Deadline, replay policy và generation boundary.

  4. Reconcile

    Per-attempt evidence, cost revision và pending state.

Một request có thể fail trước hoặc sau khi tạo billable work; mỗi transition phải có owner.

  • Alias là contract được version và kiểm chất lượng; đổi model có thể đổi behavior dù API giống.
  • Lọc privacy/region/capability/quality trước ranking cost/latency; fallback không được bỏ hard constraints.
  • Chưa thấy token không chứng minh replay safe; visible output/tool effects và upstream outcome cần state riêng.
  • Reservation bảo vệ exposure; usage ledger giữ từng billable attempt và explicit pending evidence.
  • Rate bucket, concurrency cap và durable money budget là các controls khác nhau.
  • Tenant cache key và temperature 0 không tự chứng minh access safety, freshness hoặc determinism.

1. Gateway giải quyết coordination, không thay application semantics

Application contract

  • Task/correctness, authorized tools và user-facing recovery.
  • Model alias đổi behavior cần app-specific eval qualification.

Gateway contract

  • Authenticate workload, apply data/routing policy và bound exposure.
  • Preserve attempt/stream/usage identities để diagnose và reconcile.

Provider contract

  • Actual capabilities, limits, billing/retention/regions theo deployment.
  • Unknown outcome không được diễn giải thành no work/no charge.

Khi nhiều teams gọi hosted/self-hosted models, credentials, provider limits, audit và spend attribution dễ phân tán. Gateway cung cấp shared admission/routing/observability boundary. Application vẫn sở hữu task definition, user authorization, prompt/retrieval correctness và tool-effect authority; một proxy compatible endpoint không tự biến mọi models thành interchangeable.

Chốt supported modalities, streaming/tool/schema features, aliases, priority tiers, sensitive data rules, tenant budgets và failure contract. Đặt measured overhead/SLO theo workload; mục tiêu 10–20 ms có thể là design input, không là guarantee trên mọi path. Không hứa availability vượt mọi provider khi có common dependencies hoặc correlated outages.

2. Ước lượng streams, tokens và logging riêng

Ví dụ giả định 300 applications, 50 triệu logical calls/ngày, peak 3× average, 3000 input + 500 output tokens/call và mean active stream 8 giây. Đây là workload inputs minh họa; retries/fallbacks có thể tăng upstream attempts và tokens ngoài logical calls. Little’s Law dùng stable average arrival rate và mean residence time trong cùng boundary, không nhân p99 latency như một định luật.

Peak khoảng 1736 calls/s và khoảng 13889 concurrent streams nếu peak tương đối ổn định với mean duration đó. Kích thước connection buffers, event overhead, heartbeats, TLS và slow consumers cần load tests. 14 KB raw payload/call tạo 700 GB/ngày theo decimal units; đây là counterfactual storage estimate, không là đề xuất log mọi prompt. Metadata-only logging có profile khác.

3. API contract: logical operation, attempt và config version

Public workload identity phải được xác thực; không tin tenant/team headers tự khai từ browser. API below là internal teaching contract, không claim drop-in compatibility với mọi provider. Reject unsupported features rõ ràng thay vì silently bỏ tool schemas, safety flags hoặc output format. Project attribution do trusted entitlement mapping quyết định.

          4. Tách data plane, control plane và accounting plane

          Data plane cần bounded asynchronous I/O và locally usable route snapshots, nhưng stateful admission/ledger authority phải có consistency contract riêng. Provider credentials không nằm trong application repos; adapter lấy scoped credential references. Telemetry/ledger pipeline async có durability/backpressure policy, không “fire-and-forget” rồi mất billing evidence sau crash.

          Một logical request có thể có nhiều attempts và nhiều usage records

          Sơ đồ các component; các luồng request được giải thích đầy đủ theo thứ tự bên dưới.

          Admit và stream một request

          1. Authenticate trusted workload và validate supported request/deadline.
          2. Reserve bounded quota/budget bằng logical operation identity.
          3. Pin current route/policy version và required capabilities.
          4. Choose only eligible target và create attempt ID.
          5. Dispatch normalized request theo exact provider feature profile.
          6. Forward typed chunks với bounded buffers và lifecycle state.
          7. Expose one generation identity; final/error state không nhập nhằng.

          Fallback trước expose và theo replay policy

          1. Classify 429/rejection/unknown timeout, retain attempt evidence.
          2. Check deadline, retry budget, exposure/effect state và eligible fallback.
          3. Dispatch new attempt nếu policy cho phép, reserve additional exposure phù hợp.
          4. Return replacement generation before hidden splice boundary; otherwise explicit error.

          Settle từng attempt có evidence

          1. Persist reported usage/provider request ID kể cả abandoned client.
          2. Record measured usage theo self-hosted metering contract.
          3. Deduplicate/correct per attempt; không collapse legitimate retries.
          4. Settle known charges, retain unresolved holds theo policy.
          5. Attribute scoped totals và estimated/pending differences.

          Rollout alias và governance

          1. Publish qualified versioned route set và hard data rules.
          2. Rotate scoped credentials và capability profiles.
          3. Distribute entitlement/revocation epochs theo freshness contract.
          4. Review canary quality, policy violations, latency và rollback.

          Reconcile sau disconnect hoặc gateway crash

          1. Persist interrupted state; missing final usage là UNKNOWN.
          2. Find outstanding reservations bằng durable operation/attempt IDs.
          3. Merge late evidence idempotently, compare provider aggregates/invoices phù hợp.
          4. Release/adjust holds theo explicit reconciliation policy, không usage=0 mặc định.

          5. Alias là versioned capability và quality contract

          Alias như fast hoặc smart chỉ hữu ích khi có owner, capability/context/output limits, safety/data rules và quality gates theo consuming tasks. Pinned deployment/model revisions giúp reproduce; alias rollout có config epoch và fallback set tương thích. “Model hỗ trợ tools” chưa đủ: argument schema, parallel calls, finish reasons, tokenization và error events có thể khác.

          Adapters normalize phần đã khai báo và preserve provenance/unsupported states. Không chuyển tool-enabled request sang text-only target rồi pretend success. Gateway không nên giấu every vendor distinction trong một lowest-common-denominator contract nếu ứng dụng cần specific features. Version-breaking changes có migration path; canary and rollback phải giữ credential, schema và capacity compatibility.

          6. Hard constraints trước health/cost/latency ranking

          Lọc entitlement, endpoint/region/data-retention rules, capabilities, context size và task-specific qualification trước chọn cost/latency. Healthy endpoint vẫn có thể illegal cho data class hoặc quality chưa đủ. Prediction có uncertainty; ưu tiên cheapest không được hạ chất lượng âm thầm. Fallback capacity/correlated dependencies phải được reserve/test chứ không chỉ ghi trong config.

          7. Replay safety không chỉ là “chưa stream token”

          Phân loại validation/auth errors, capacity 429, connection failure, server errors và timeout có outcome unknown. Connection fail trước dispatch khác request đã đến provider nhưng response mất. Nếu pure generation được policy cho replay, fallback có thể chấp nhận duplicate compute/cost; nếu operation có side effects hoặc nondeterministic commitments, cần application/sink idempotency và recovery contract. Request ID do gateway gán không tự được provider hoặc tool sink honor.

          Track bytes/events đã expose, tool outputs/effects và generation identity. Sau partial output, không âm thầm nối một model run khác như cùng câu trả lời. Surface interruption hoặc dùng explicit replacement/resume contract do app hỗ trợ. Retry/fallback trước expose vẫn phải pass operation replay policy, remaining deadline, attempt budget và all hard constraints.

          8. RPM, token rates, concurrency và spend không cùng đơn vị

          Requests/sec bảo vệ CPU/abuse; token rates phản ánh workload theo provider contract; concurrency caps bảo vệ streams, memory và capacity; durable spend budgets giới hạn financial exposure. Provider có thể tách input/output/cache dimensions và tổ chức/workspace/model groups; không assume một global combined TPM bucket đúng cho mọi vendor. Limiter adapter phải hiểu cách provider estimate và reconcile tokens.

          Hierarchical controls gồm org/provider pool, tenant/team/project và priority classes. Reserved shares/headroom có thể bảo vệ interactive traffic, nhưng cần borrowing/reclaim policy và bounded queues/deadlines để tránh starvation. 429 có thể mang Retry-After; parse delay/date theo contract khi có, respect và add bounded jitter, nhưng không retry forever nếu nguyên nhân là entitlement/spend hard cap. SDK retries và gateway retries phải có một end-to-end attempt budget.

          9. Reserve trước dispatch, settle theo evidence

          Reservation lifecycle có owner

          1. Hold

            Atomic operation-scoped hold trước external dispatch.

          2. Attempt

            Persist attempt/deployment/provider IDs và exposure.

          3. Evidence

            Merge known usage; missing final event giữ pending state.

          4. Adjust

            Idempotent settlement/corrections và explicit release policy.

          Crash có thể xảy ra giữa mọi cặp bước; UNKNOWN không là settled-zero.

          Output chưa biết trước, nên reserve bounded exposure theo countable input, max output và allowed attempts/pricing assumptions. Estimate cần tokenizer/profile và tool/multimodal overhead phù hợp; reservation không mặc nhiên exact upper bound nếu vendor có additional billable categories hoặc retries ngoài hold. Atomic check-and-hold chống concurrent overspend; idempotent admission gắn operation scope và request payload hash.

          Budget reservations, metered usage và rate-limit token buckets không nên gộp bằng một refund function mơ hồ. Refillable buckets có time/cap semantics; durable financial holds phải survive crash, tránh duplicate release/settle và carry unresolved liabilities. Tính budget available = limit − settled exposure − outstanding holds theo consistent policy; guard cho additional exposure thay vì mặc định actual luôn nhỏ hơn reserve.

          10. Logical requests, attempts và usage event versions

          Một logical request có A1 timeout và A2 thành công; cả hai có thể tạo billable work. Ledger có parent request ID để user attribution và child attempt IDs để metering. Dedup event replay theo provider/attempt/event identity hoặc cumulative usage revision; không dedup tất cả bằng request ID rồi bỏ A2. Ngược lại cộng mọi cumulative stream sample cũng double-count; adapter phải distinguish delta/cumulative/final evidence.

          Giữ provider request ID, deployment/model version, quantities theo category, currency/rate version, evidence source, estimated/final/pending state và correction history. Không sửa history âm thầm; adjustments có lineage. Provider-reported usage là authoritative evidence theo contract nhưng có thể đến muộn/thiếu hoặc khác invoice rounding/categories; reconcile available reports. Client disconnect không chứng minh upstream compute/billing đã stop và cancellation receipt không luôn final usage.

          11. Streaming: bounded memory và explicit lifecycle

          Use async I/O, bounded buffers, flow control/backpressure và resource limits cho slow consumers. Incremental forwarding không đồng nghĩa tuyệt đối zero buffering: protocol parsing/coalescing/TLS vẫn cần bounded buffers. Configure reverse-proxy buffering, idle/overall timeouts, heartbeats và cancellation propagation; load test connection churn, stalls và gateway draining.

          HTTP 200 lúc mở stream không bảo đảm complete generation. Typed content/usage/error/final events có provider-specific ordering; parser cần handle partial frames, unknown supported-version events, tool argument fragments và terminal interruption. Do not fabricate valid JSON from truncated tool output or execute partial arguments. Resume requires explicit retained state/idempotency rather than replay-from-zero presented as continuity.

          12. Cache identity, permissions và freshness

          Exact response reuse cần opt-in task semantics, full relevant request/context/tool/schema/settings/model contract, tenant/principal/access scope và dependency/policy versions. Temperature 0 không là universal determinism guarantee; exact-key reuse có thể phục vụ stale data hoặc skip intended tools. Tenant boundary alone không đủ nếu cùng tenant có users với permissions khác. Hit vẫn cần current authorization/freshness checks theo contract.

          Semantic similarity không chứng minh same question/authorization/action. Chỉ dùng trên explicit eligible task classes với validation, scope và measured wrong-reuse risk; không universal “FAQ là safe”. Response cache khác prefix KV cache của provider/model runtime, vì prefix reuse vẫn generate answer mới và có compatibility/residency rules riêng. Do not serve payloads across revoked scopes hoặc fall back to a stale answer vì provider down nếu contract không cho phép.

          13. Credentials, data egress và minimized logs

          Gateway tập trung sensitive traffic nên tăng blast radius nếu controls yếu. Dùng workload identity, least-privilege provider credentials, rotation/revocation, separate admin/data-plane permissions và audited config. Data classification/region/retention/training restrictions phải match exact endpoint/contracts; self-hosted không tự có privacy hoặc security nếu logs/storage/network mở.

          Default log usage/timing/error categories với scoped pseudonymous IDs, không full prompts/responses. Redaction có false negatives và không thay data minimization, access controls, encryption/retention/deletion. Debug payload capture cần explicit scope, bounded duration/access và policy enforcement trước transmission/storage. Even metadata có thể reveal customers/projects; keep required audit/billing evidence under appropriate retention rather than “always public metadata”.

          14. Data model và consistency boundaries

          RouteVersion binds alias contract, targets, capability/data constraints, qualifications, weights, credentials refs và rollout epoch. RequestOperation binds authenticated scope/payload hash, deadline, policy version và result state. Attempt binds deployment/provider IDs, dispatch/exposure/terminal states và usage evidence refs. Reservation binds authority epoch, amount, state và idempotent settlement lineage. UsageAdjustment binds attempt, evidence revision và rate version.

          Trace IDs giúp correlate, không tự enforce uniqueness/exactly-once. State transitions cần storage constraints/CAS/transactions và outbox/inbox khi publish durable events. Không assume quota cache và ledger transaction cross-service atomic; define recovery for hold-without-dispatch, dispatch-without-response và usage-without-settlement. Reconciler ownership/fencing prevents stale workers from double applying corrections.

          15. Multi-region và quota-store outage có trade-off

          Data planes across zones/regions giảm một số failures nhưng shared DNS, auth, quota store, credential system và upstream org limits vẫn có thể correlate. Last-known-good config cần validity/revocation freshness bounds. Existing streams drain/checkpoint theo actual protocol; reconnect có thể phải explicit new generation, không transparent continuation guarantee.

          Khi quota authority unavailable, fail-open không universal safe. High-risk/hard-budget tenants có thể fail closed; low-risk tier có thể dùng preallocated local leases/tokens với bounded exposure và fencing. Regional allocations/escrow đổi utilization/fairness lấy bounded overshoot; eventual counters alone không enforce strict global cap. Chốt spend/availability/data rules và incident override ownership trước outage.

          16. Quality, cost và operations cùng quyết định route rollout

          Track latency distribution theo admission/queue/first useful event/finish, token categories, eligible-route exhaustion, attempts per logical call, 429 reason, pending usage age, budget exposure và data-policy violations. Success HTTP rate không đủ nếu output schema/tool behavior hoặc task quality giảm. Segment by team/task/region/model revision; keep explicit denominators và censored/abandoned streams.

          Aliases đổi model/prompt/adapter cần task-specific regression/security suites, load/capacity validation, shadow/canary có privacy controls và rollback triggers. Shadow traffic vẫn tốn tiền và expose data; không execute real tools hai lần. Cheapest advertised per-token price không quyết định self-hosted TCO: utilization, hardware, staff, warm capacity và redundancy đều ảnh hưởng. Build/adopt dựa trên actual required policies/integration/operations thay vì một câu “tự build linh hoạt hơn”.

          17. Luyện quyết định LLM Gateway

          Primary trả 429 ở peak, làm gì trước?

          Classify scope/reason, respect available Retry-After, bound attempts/jitter/deadline và protect priority shares. Chọn only qualified fallback nếu remaining budget/capacity/data rules cho phép. Không retry spend/entitlement hard cap vô hạn hoặc để SDK×gateway retries nhân load.

          Timeout trước first token có chắc replay safe?

          Không: upstream có thể generate hoặc execute tool dù response mất. Pure generation replay cần policy cho phép duplicate work/cost; side effects cần sink idempotency/recovery. Exposed stream state chỉ là một trong các boundaries.

          Vì sao dedup usage chỉ theo request ID sai?

          Một request có nhiều billable attempts. Dedup duplicate reports trong từng attempt và hiểu cumulative revisions; giữ parent attribution riêng. Request-only có thể undercount A2, còn no dedup có thể cộng lại A1.

          Client disconnect mà final usage mất thì refund hết?

          Không mặc định usage=0. Persist pending state/known lower evidence, reconcile late reports và apply explicit expiry/risk policy. Cancellation không chứng minh upstream billing stopped. Bound outstanding liabilities để outage không thành uncontrolled overspend.

          Quota store down thì fail-open có tốt không?

          Không universal. Hard caps/data policy có thể require fail closed; local preallocated allowances có bounded risk nếu issuance/epoch/recovery đúng. Chọn trước theo tenant risk và availability contract, không unbounded eventual counters.

          Cache temperature 0 và tenant key có safe không?

          Không đủ: generation có thể nondeterministic; users cùng tenant có permissions khác; context/model/tool/dependency versions và freshness matters. Reuse eligibility/current access checks phải explicit.

          Alias fast đổi provider mà API giống, cần eval lại?

          Có: capability/quality/error/usage/tool/schema semantics có thể khác. Qualify task slices, pin versions, canary và rollback compatible config. Stable alias name không là behavior guarantee.

          Tính concurrent streams từ QPS như nào?

          Trong cùng boundary và stable window, average concurrency≈arrival rate×mean residence time; ví dụ1736.11/s×8s≈13889. Tail/slow-consumer buffers/load distribution vẫn cần đo và capacity headroom; không sum/multiply arbitrary percentiles thành guarantee.
