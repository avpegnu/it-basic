1. Search index và serving là scope riêng

Relevance

  • Query intent, candidate recall và judged quality; không chỉ score cao.

Freshness

  • Track source/ingest/writer/reader generations và deletes.

Latency / safety

  • Tail budgets, completeness và quyền hiện hành đi cùng results.

Bài Web Crawler tạo corpus; Autocomplete gợi ý query; bài này xây keyword search có ranked results, filters, snippets, pagination, updates/deletes và visibility SLO. Chọn corpus trước: public web cần spam/link/quality signals; internal/site/product search cần fields, ACL, facets và tenant routing. Không mặc định một ranking formula dùng tốt cho mọi sản phẩm. Hybrid/vector retrieval nối được pipeline nhưng không thay lexical correctness và authorization.

Chốt p99 latency theo query class, freshness từ source commit tới searchable result, result completeness và relevance metrics. Một illustrative 200 ms query target khác ingest freshness vài giây; write accepted, document retrievable by ID và keyword searchable là contracts khác nhau. Product cần nói partial results có được phép không và stale authorization/delete có được chấp nhận không.

2. Fan-out nhân query work, replicas nhân storage

Giả định một tỷ documents, text trung bình 10 KB: raw 10 TB thập phân. Chọn hypothetical primary index 3 TB để tính, không suy từ raw text vì stored fields, positions, analyzers, vectors, compression và mappings thay ratio. Nếu dùng 64 primary shards thì trung bình 46,875 GB/shard; một replica thêm mỗi primary cho tổng khoảng 6 TB index copies trước merge/rebuild/headroom. Shard-size heuristics không thay benchmark actual query/update distribution.

Peak 10.000 queries/giây fan-out đủ 64 eligible shards tạo 640.000 shard requests/giây trước hedges. Tenant/time/routing pruning có thể giảm eligible set; replicas thường chia query load, không có nghĩa query phải hỏi mọi replica. At K=100/shard, 64 shards trả tối đa 6.400 candidates/query; mỗi candidate giả định 32 bytes thì khoảng 204,8 KB/query và 2,048 GB/s merge ingress tại peak, chưa protocol/features. Model rerank pool nhỏ hơn vẫn cần candidate recall đủ.

Indexing capacity cần update bytes/s, reader refresh cadence, merge amplification, deleted-doc pressure và full reindex coexistence. Small shards tăng scheduling/metadata/fan-out overhead; quá large shard làm recovery/rebalance lâu và query work nặng. Size theo measured heap, CPU, disk bandwidth, cache working set, failure-domain loss và repair time; document count alone không phản ánh postings/cardinality.

3. API trả visibility và completeness rõ

Search request có query grammar/mode, filters, pagination/sort context và authenticated principal từ server-side session. Response có result IDs/versions, bounded snippets, next cursor, index/ranking generation và partial/missing-shard status. Không trust tenantId/ACL client tự đưa như quyền; server derives/enforces scope. Query timeout khác empty result: zero matches và failed shard không được gộp một status.

Index update/delete có stable document ID và monotonically interpreted source version hoặc comparable revision token. Accepted response mô tả durability boundary và optional visibility wait token; writer ACK không mặc định immediate search visibility. Bulk errors phân per-item, có bounded retry và order/version rules. Delete retention/rebuild protocol phải chống late stale upsert, nhất là sau tombstone cleanup.

          4. Hai pipelines chia sẻ versioned readers

          Query service parse/rewrite bounded query, derive permission/filter scope và check scoped cache. Coordinator route eligible shards, merge local candidates rồi bounded rerank/hydrate. Ingest/indexer apply source changes và publish reader generations; merge/lifecycle giảm segment overhead và reclaim old bodies. Evaluation theo cả query quality lẫn freshness/latency, không chỉ health endpoints.

          Sơ đồ có query/cache/update/delete/rebuild traces. Replica routing phải biết compatible reader/schema/sort semantics; failover hoặc reindex không tự cho phép mix incompatible scores/cursors. Một global coordinator có thể scale stateless nhưng response correctness vẫn phụ thuộc query context, authorized candidate pool và completeness policy.

          Query serving và index publication gặp nhau ở reader generation

          Sơ đồ các component; các luồng request được giải thích đầy đủ theo thứ tự bên dưới.

          Ingest acceptance, reader refresh, physical merge và authorization có boundaries riêng. Coordinator chỉ gọi eligible shards và phải nêu completeness khi thiếu shard.

          Query miss tới page

          1. Send query/filter/cursor cùng current principal.
          2. Cache miss; compile authorized bounded retrieval plan.
          3. Route eligible shards, one suitable replica mỗi shard, deadline/hedge budget.
          4. Return authorized candidates, scores/sort keys và completeness metadata.
          5. Merge comparable scores và choose bounded candidate pool.
          6. Rerank rồi recheck current rights/version trước snippets.
          7. Return results/cursor cùng generation/partial status.

          Scoped cache hit

          1. Same query chưa đủ nếu principal/filter/generation khác.
          2. Lookup compatible query/filter/auth/index/rank key.
          3. Cached candidates vẫn cần current access/delete policy enforcement.
          4. Return bounded authorized content, không leak cached forbidden snippets.

          Update thành searchable reader

          1. Emit source-versioned document change.
          2. Replay identified change; reject stale version theo supported scope.
          3. Build/open compatible segments rồi publish reader generation.
          4. Measure source/accept-to-visible lag, không chỉ writer ACK latency.

          Delete, stale replay và reclamation

          1. Delete/ACL revocation mang version và scope.
          2. Keep version/tombstone guard; old update không revive delete.
          3. Publish delete visibility theo refresh policy; rights enforcement có own strictness.
          4. Merge reclaim obsolete bytes khi readers/pins an toàn, giữ needed guards.

          Reindex và rollout schema/ranking

          1. Consistent snapshot cut và compatible ordered tail vào new generation.
          2. Build/warm new readers; verify coverage, versions và permissions.
          3. Gate ranking/schema rollout bằng quality/freshness/latency evidence.
          4. Atomic alias/generation switch; old pagination context có expiry policy.

          5. Term dictionary, postings và positions

          Từ text tới bounded candidate set

          1. Analyze

            Compatible terms, field semantics và query mode.

          2. Retrieve

            Lookup/intersect/union postings, apply allowed scope.

          3. Score / prune

            BM25/features và safe candidate budgets.

          4. Explain / hydrate

            Trace score và authorized fields/snippets.

          Index structures giảm scan nhưng broad query vẫn có work cost.

          Term dictionary + postings

          • Dictionary tìm term; postings chứa doc IDs/tf/positions cần cho match và score.
          • Positions phân biệt phrase với chỉ AND: ở d1, cache=[0,3], redis=[1], nên cache redis liền nhau tại 0–1.

          Stored fields + doc values

          • Stored fields lấy các giá trị của một document để hydrate response; không tự grant quyền.
          • Doc values phục vụ field-oriented sort/facet/aggregation và features theo mapping; không thay inverted text index.

          Inverted index map term tới sorted doc IDs, term frequency và optional positions/offsets. AND query intersect posting lists, thường bắt đầu rare list rồi skip/block structures; OR hợp lists và score candidates. Phrase/proximity cần positions, không chỉ cả hai từ có trong document. Term dictionary/FST giúp lookup/prefix; stored fields phục vụ retrieval/snippets; doc values là column-oriented access cho sorting/facets/features. Query còn có thể đọc field data cho scoring/filter, không chỉ đọc documents khi làm snippet.

          Index/query analysis phải tương thích, không nhất thiết byte-identical: query-time synonym expansion hoặc dedicated search analyzer có thể khác có chủ đích. Chốt Unicode normalization, accents, token boundaries, language stemming, stopwords và keyword fields. Tiếng Việt có segmentation/multi-syllable terms nên lowercase+space split không là production analyzer đầy đủ. Analyzer change có thể cần reindex và versioned rollout; test queries nhiều ngôn ngữ, names, IDs và mixed code/text.

          6. BM25 là retrieval score, không phải relevance truth

          Một common teaching formulation cộng theo query terms: IDF=ln(1+(N−df+0,5)/(df+0,5)); contribution=IDF×tf×(k1+1)/(tf+k1×(1−b+b×dl/avgdl)). tf saturation giảm lợi ích spam lặp từ; b điều chỉnh length normalization. Field boosts, norms/compression, term overlap và implementation details có thể đổi absolute score. Lab dùng exact small-corpus arithmetic với k1=1,2, b mặc định0,75, không khẳng định tái tạo mọi Lucene score.

          Lab hiển thị postings/tf/positions, corpus length và per-term score explanation cho query English. Shared corpus statistics làm scores comparable trong fixture. Production document-sharded indexes có local statistics khác nhau; global-stat query phase hoặc calibrated scoring có trade-offs về latency/work. Safe top-K merge theorem chỉ áp khi same fixed score/total order và mỗi shard trả đủ local K; later rerank theo new features có thể cần oversampling để không miss best candidate.

          idf(term) = ln(1 + (N - df(term) + 0.5) / (df(term) + 0.5))
norm(d) = k1 * (1 - b + b * length(d) / averageLength)
score(d,q) = sum(idf(t) * tf(t,d) * (k1 + 1) / (tf(t,d) + norm(d)))

N: documents in the chosen statistics scope
df: documents containing the term
k1: nonnegative saturation parameter
b: length normalization in [0,1]

          BM25 teaching formulation; các biến thuộc cùng field/statistics scope.

          7. Filter trước top-K và kiểm quyền tại hydration

          Retrieve safely

          • Eligible documents vào candidate pool, không truncate forbidden pool trước.

          Hydrate safely

          • Current rights, version/delete checks và escaped snippets.

          Cache safely

          • Scope/generation/freshness áp dụng cả metadata và counts.

          Nếu top2 gồm private d2 và public d5, lọc d2 sau ranking chỉ còn một result dù public d1 đủ tốt vẫn nằm ngoài pool. Apply ACL/tenant/business filters vào retrieval trước candidate truncation khi cần đúng eligible recall. Rerank/hydrate/cache cũng enforce quyền: stale index ACL có thể cần current-authority validation để đáp ứng strict revocation SLO. Kiểm ở cuối giúp chặn leak nhưng không tự lấy lại authorized candidates đã bỏ; cần refill/retrieval policy rõ.

          Cache keys gồm normalized query/filter/sort, effective permission scope/version và index/ranking generation theo freshness contract. Shared popular-query cache không được reuse private snippets giữa tenants. Result counts/facets/suggestions/error timing cũng có disclosure risk; access checks không chỉ hide body text. Snippets escaped/sanitized, highlight markers không được execute source HTML/script. Internal fixture deliberately exposes all toy texts để giải thích algorithms, không là production permission design.

          8. Durability, refresh và merge là ba trục

          Recoverable ingest/writer acceptance có log/replication/persistence contract riêng. Refresh mở/publish reader mới cho changes searchable, có thể không cần full durable index commit. Merge kết hợp segments và reclaim obsolete bodies/deletion bits dưới reader-safe policy; nó không phải bước bắt buộc trước mỗi durability ACK. Không vẽ một linear pipeline buffer→refresh→merge→fsync như mọi write phải đi qua đủ theo thứ tự đó.

          Versioned update/delete guard chặn old CDC event sau newer delete. Tombstone/version metadata retention phải cover supported replay/rebuild window, hoặc có authoritative snapshot/reconciliation thay thế. Lab v1 body→v2 delete→refresh→latev1→refresh cho thấy guard-off resurrect; merge reclaim old bytes không tự sửa resurrected current state. Search invisibility không là physical erasure khỏi mọi replica/snapshot/backup.

          Faster refresh có thể tăng small segments/merge work và query tails; choose freshness SLO theo data class/workload. Read-your-write wait token hoặc limited primary overlay có thể phục vụ own edits nhưng overlay cần query/filter/rank/dedup/delete semantics, không chỉ append changed document vào mọi result page. Không hứa globally fresh total ordering khi index còn lag.

          9. Tail latency tăng theo fan-out và correlation

          Partition theo document

          • Mỗi shard có index của một phần documents; coordinator gửi query tới tập shards có thể chứa kết quả.
          • Giữ intersection/scoring gần dữ liệu; routing có thể prune shards, nhưng broad query vẫn chịu fan-out/tail.

          Partition theo term

          • Chỉ cần liên hệ owners của query terms, nhưng broad/popular terms có postings rất lớn và hot owners.
          • Cross-owner intersections cần ship postings hoặc distributed protocol; ít contacted shards không tự đồng nghĩa ít work.

          Nếu N eligible shards độc lập có per-shard slow probability p, xác suất ít nhất một slow là 1−(1−p)^N. N=100,p=1% cho khoảng63,4%, không phải query p99 cố định63,4%: đây là threshold-event probability tại một slow definition. Shared overload/AZ/network correlation phá independence. Query completion có parse/routing/merge/rerank/hydrate overhead ngoài max shard response; instrument full critical path.

          Replicas/load-aware routing có thể giảm tails; bounded hedging gửi replica khác sau delay nếu original còn pending. Extra requests tốn CPU/network và có thể làm overload tệ hơn; use request budgets, correlation-aware routing, cancellation và admission. Deadline có thể fail closed hoặc explicit partial theo product; thiếu shard không được báo complete global top-K/counts/facets. Partial pagination còn cần stable completeness semantics.

          Lab tách analytical N/p panel khỏi fixed four-shard trace, tránh lấy toy timings làm benchmark. Primary durations30/40/180/55 ms; backup service times90/90/45/90 ms. Hedge delay30 làm slow shard hoàn tất75 ms và tạo thêm3 requests; deadline80 không hedge trả partial3/4 hoặc fail. Chọn latency policy phải nhìn cả quality/completeness và resource amplification.

          10. Retrieval, ranking và reranking có recall budgets

          Spending relevance compute có chủ đích

          1. Match / filter

            Authorized scope và broad affordable candidates.

          2. Cheap ranking

            Comparable scores, bounded per-shard pools.

          3. Rerank / diversify

            Versioned features/models và fallback.

          4. Hydrate / evaluate

            Rights, snippets, quality/freshness slices.

          Mỗi truncation cần đo relevant candidates bị bỏ.

          Candidate generation dùng lexical/postings hoặc hybrid sources; cheap features/BM25 chọn larger pool; learning-to-rank/neural rerank chỉ xử lý bounded subset. Model không cứu relevant document chưa vào pool. Measure recall theo stage, languages và query intents; tune oversampling/diversity/dedup để không toàn near-duplicate pages. Feature freshness, model version, deterministic ties và timeout fallback là response contract.

          Web corpus thêm link authority/spam/trust/freshness; commerce có availability/price/category và business policies. Learned behavior signals có position/popularity bias và feedback loops; test niche/new items. Score magnitudes giữa lexical/vector/model không mặc định comparable; hybrid normalization/fusion phải có evaluation. RAG dùng retrieved documents còn cần provenance/context constraints được mở sâu ở AI Systems.

          11. Cursor cần total order và stable reader context

          Deep offset pagination bắt shards thu thập skipped hits cộng page hits, tăng memory/CPU/merge work. search-after dùng last sort tuple nhưng không freeze updates giữa pages. Point-in-time/snapshot reader cùng deterministic total sort/tiebreaker hỗ trợ consistent traversal; internal doc IDs có thể khác replicas và thay sau merges nên không dùng như universal external identity ngoài supported snapshot scope.

          Cursor opaque/signed bind query/filter/principal scope, sort, ranking/index generation và expiry. Snapshot pin giữ old segments gây resource pressure nên bound lifetime/open contexts và cleanup. ACL revoke/delete strictness có thể cần override old snapshot content; product cần nói stable traversal nhưng current rights vẫn enforced như thế nào. Reindex alias switch không silently đổi reader giữa cùng cursor chain; expired context trả reset contract rõ.

          12. NDCG dùng independent judgments, không tự chấm returned pool

          Giữ judged query set đại diện languages/intents/head-tail và graded relevance, có version/annotation criteria. DCG@K cộng (2^rel−1)/log2(rank+1); IDCG lấy best ordering từ judged candidate universe cho query, không chỉ sort các hits hệ thống vừa trả. Nếu only returned mediocre item được sort làm ideal, metric có thể 1 dù hệ thống miss excellent documents. IDCG=0 cần declared undefined/skip/zero convention và reporting coverage.

          Ví dụ judgments excellent=3, okay=1, bad=0. Return only okay cho DCG1, nhưng IDCG@2 là 7+1/log2(3), nên NDCG khoảng0,131; không phải1. Offline gates còn cần candidate recall, zero-results, permission correctness, freshness và latency slices. Unjudged không đồng nghĩa chắc irrelevant; track missing labels. Click/reformulation/abandonment trong A/B bị position bias và query-mix effects, nên dùng guardrails/segmentation chứ không tối ưu CTR đơn lẻ.

          13. Reindex, recovery và resource isolation

          New analyzer/mapping/schema generation build từ consistent source cut và compatible versioned tail. Verify document/delete coverage, permissions, queries và performance trước alias/generation switch; pin old pagination readers hoặc expire rõ. Keep old generation có rollback window nhưng không restore revoked content qua unsafe stale aliases. Snapshot/recovery cần indexes, source/version checkpoints và retained tombstone strategy, không chỉ copy segment files rồi đoán latest.

          Bound query complexity: wildcard/regex/fuzzy expansions, script costs, aggregation cardinality, returned fields/snippet size và per-tenant concurrency. Isolate foreground query pools khỏi refresh/merge/rebuild, nhưng vẫn reserve enough indexing capacity để freshness không chết. Monitor merge backlog/disk temporary space/reader pins/cache churn và hot shards. DLQ malformed ingest giữ source identity/version để repair/replay an toàn.

          14. Chứng minh query quality cùng recovery correctness

          Algorithm evidence

          • Exact small corpus, score contributions và independent judged sets.

          Boundary evidence

          • Visibility/deletion versions, permissions và snapshot cursor contexts.

          Failure evidence

          • Partial shards, correlated tails và maintenance resource contention.

          Trace ingest accepted→writer applied→reader visible và query parse→eligible shards→candidate merge→rerank→authorized hydration. Report p50/p95/p99 theo query class, shard completeness, source-to-visible lag, deleted/unauthorized result probes, stage recall, zero-result rates và resource cost. Cache-hit rate cao không chứng minh quality/freshness; score lớn không chứng minh relevance.

          Fault tests gồm delayed/stale source updates sau delete, duplicate ingest, shard timeout/replica failover, hedge storm, full disk/merge stall, analyzer rollout mismatch, old PIT expiry và permission revoke trên cached results. Compare against small exact baseline để kiểm postings/ranking/ties/ACL và stable pagination. Review completeness policy bằng missing-shard test, không chỉ all-green cluster.

          15. Luyện giải thích từ postings tới response contract

          Vẽ query cache redis có private top candidate, slow shard và recent deleted document. Hỏi filter ở đâu, score statistics scope nào, missing shard có làm page complete không và cached snippet còn quyền không. Sau đó paginate qua refresh/reindex và tính NDCG khi excellent document không được retrieve.

          Index/query analyzer có bắt buộc identical không?

          Không nhất thiết. Terms/positions/query semantics cần compatible; dedicated search analyzer/synonyms có thể khác có chủ đích. Version và test reindex requirements, nhất là multilingual text.

          Tại sao filter ACL sau top-K không đủ?

          Nó có thể block leak cuối cùng nhưng underfill/miss authorized candidates đã bị truncate. Apply eligible scope trong retrieval và enforce current rights xuyên cache/hydration; refill nếu strict revocation drops candidates.

          Refresh có đồng nghĩa durable fsync commit không?

          Không. Refresh publish searchable reader; acceptance/recovery persistence và merge lifecycle khác boundaries. Chọn guarantees bằng storage protocol, không suy từ searchable result.

          Shard local top-K merge lúc nào exact?

          Khi fixed comparable scores/total order và đủ local K cho global K trên eligible set. Local statistics khác hoặc later rerank thay scoring có thể cần extra protocol/candidate oversampling; missing shard phá completeness.

          Hedge luôn làm hệ thống nhanh hơn không?

          Không. Extra load/correlation/cancellation delay có thể tăng overload. Budget, measure tails và completeness, choose delay dưới actual capacity; toy min(primary,delay+backup) bỏ nhiều costs.

          search_after có freeze index qua pages không?

          Không. Stable reader/PIT cùng total sort/tiebreaker và context binding mới hỗ trợ stable traversal; permission/deletion/expiry policy vẫn phải define.

          NDCG ideal có lấy từ returned hits thôi không?

          Không để đánh giá retrieval/ranking đầy đủ. Cần independent judgments để missing excellent docs bị phạt; handle unjudged và IDCG0 explicit. Return only okay trong worked example không score1.

          Delete đã invisible thì merge có thể quên version guard ngay không?

          Không nếu supported replay còn stale updates. Retain version/tombstone metadata hoặc authoritative rebuild/cutoff protocol; physical reclamation không cho phép resurrection.
