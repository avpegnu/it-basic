Thiết kế Video Platform: upload, ABR và CDN

Tách ingest/processing khỏi playback; thử progressive publication, buffer khi bandwidth đổi và viewer/origin bandwidth để hiểu quality, availability và resource trade-off.

Từ một upload tới từng segment playback

  1. Upload có thể resume

    Session/scoped parts, integrity và verified source version.

  2. Encode và publish

    DAG, task retry, gate và manifest generation.

  3. Adapt và deliver

    Player chọn compatible bitrate; CDN giữ media bytes.

  4. Đo QoE và tài nguyên

    Startup/stall, storage/compute/egress và recovery.

Học từng durable/authorization boundary rồi mới tối ưu compute và byte.

  • Verified upload không đồng nghĩa playable; publish pointer chỉ trỏ tới validated assets sau mandatory gates.
  • DAG task identity, immutable outputs và generation guards giữ retry/cancel/publication đúng state.
  • ABR cân bằng quality với startup/stall; network estimate không biết trước bandwidth giảm.
  • CDN giảm origin fills, không xóa viewer bytes; sizing dùng bitrate × watch time và byte hit ratio.
  • Codec, ladder, playback auth và multi-CDN đều cần capability/policy/QoE đo được, không có một cấu hình tối ưu chung.

1. Hai hệ thống: ingest và playback

Time-to-playable

  • Upload hoàn tất khác playable: còn integrity, probe, encode, packaging và publish gate.

Playback QoE

  • Startup, rebuffer, chất lượng/switch và lỗi theo device/ISP/region.

Bytes và quyền

  • CDN giảm origin load, không xóa viewer egress; cached media vẫn cần access policy phù hợp.

Video platform gồm pipeline biến upload thành playable assets và delivery path đưa bytes tới viewer. Control API quản lý owner, metadata, state và playback authorization; data plane xử lý object upload, transcoding, CDN và player. Tách hai đường giúp scale/failure độc lập và tránh bắt app server proxy mọi GB. Đây là lựa chọn của baseline, không phải quy luật cấm mọi proxy upload ở mọi sản phẩm.

Baseline là on-demand video, resumable upload, nhiều rendition/codec tương thích thiết bị, title/thumbnail/caption và playback mượt. Live, recommendation, comments, ads là scope khác. Mục tiêu first frame dưới 2 giây và publish trong vài phút phải gắn device/network cohort, file size và processing workload; không hứa đạt trên mọi video 4K và mạng chậm.

2. Egress, ingest và rendition size phải tính riêng

Ví dụ 50 triệu DAU × 5 view × 600 giây/view × 3 Mbit/s cho khoảng 56,25 PB viewer bytes/ngày, tương đương 5,21 Tbit/s trung bình. Watch seconds và delivered bitrate là input có thể khác lớn theo product/device; số view không tự nói được bandwidth. CDN cache hit không loại các bytes đã gửi tới viewer.

500.000 upload/ngày × 300 MB raw là 150 TB ingest/ngày. Encoded storage không tự bằng 1–1,5 lần raw: tổng gần Σ(duration × rendition bitrate / 8) cộng audio/container/metadata. Với video mẫu dài 600 giây và ladder tổng 11,7 Mbit/s, các rendition tốn khoảng 877,5 MB/video nếu tạo đủ, tức 438,75 TB/ngày ở cùng upload count. Chỉ tạo resolution/codec phù hợp source/client và policy; không upscale nguồn thấp chỉ để đủ ladder.

3. Upload session, completion và playback session

Create/complete cần idempotency theo owner/session. Signed request bị giới hạn vào đúng object/part/operation và thời hạn; refresh URL không tạo một video mới. Không trả hàng nghìn part URL chưa cần nếu có thể cấp theo page. Complete endpoint kiểm server-side storage result, size, integrity và object version thay vì tin client khai đủ part.

POST /videos

Tạo video/upload session của principal được phép.

Idempotency-Key: upload-action-42
{ "title": "Demo", "size_bytes": 300000000, "content_type": "video/mp4" }
201 { "video_id": "v42", "upload_session_id": "u42", "state": "UPLOADING" }

    POST /videos/{id}/upload-parts

    Cấp hoặc refresh scoped part requests cho cùng session.

    { "upload_session_id": "u42", "part_numbers": [1,2,3] }
    200 { "parts": [{ "number": 1, "url": "https://upload.example/opaque-signed-request", "expires_at": "..." }] }

      POST /videos/{id}/complete

      Complete/verify source rồi ghi processing intent có recovery.

      { "upload_session_id": "u42", "parts": [{ "number": 1, "etag": "opaque" }], "checksum": "..." }
      202 { "state": "PROCESSING", "source_version": "s3" }
      • ETag không mặc định là MD5/checksum toàn file, đặc biệt multipart; dùng checksum/verification đúng contract storage.

      GET /videos/{id}

      Metadata theo visibility/owner; PROCESSING chưa được trả playback như READY.

      200 { "title": "Demo", "state": "READY", "asset_version": "a7", "available_renditions": ["low","mid"] }

        POST /videos/{id}/playback-sessions

        Kiểm entitlement/device/region rồi cấp manifest/session access.

        201 { "manifest_url": "https://media.example/v42/a7/master.m3u8", "access": "opaque-scoped-session", "expires_at": "..." }

          DELETE /videos/{id}

          Chuyển desired state, chặn publication cũ và thực hiện takedown/cleanup theo policy.

          202 { "state": "DELETING" }

            4. Control plane và data plane tách rõ

            Metadata DB giữ desired/publication state, source version và pipeline generation; raw/encoded bucket không là API public để bypass quyền. Processing jobs dùng stable identity và durable admission; object events có thể trùng hoặc out of order nên consumer phải kiểm source/session version. Outbox/reconciliation liên kết storage completion với database/job state vì chúng thường không nằm trong một transaction chung.

            Playback API không proxy mọi segment và viewer không truy cập DB trực tiếp. Nó kiểm quyền và cấp access tới published asset version; CDN/player làm phần media transfer. Mỗi arrow cần định nghĩa retry, deadline và bytes/state owner, đặc biệt khi job cũ hoàn tất sau cancel/delete.

            Upload/processing và playback là hai đường riêng

            Sơ đồ các component; các luồng request được giải thích đầy đủ theo thứ tự bên dưới.

            API quản lý quyền/state, object storage giữ media bytes, CDN phục vụ playback. Publish chỉ sau artifact và gate đủ điều kiện; đây là kiến trúc minh họa.

            Create và resume upload

            1. Tạo video với idempotency key, metadata và expected size.
            2. Commit owner/session ở UPLOADING; key object không trùng upload khác.
            3. Trả video/session identity đã commit.
            4. Cấp signed part requests có scope/expiry; refresh URL theo cùng session khi cần.
            5. PUT các part trực tiếp; retry part lỗi, giữ checksum/progress.
            6. Storage xác nhận part; object cuối chỉ tồn tại theo semantics completion của storage.
            7. Yêu cầu complete; server kiểm ownership/session và verify storage result.
            8. Complete/verify object size, integrity và exact source version.
            9. Object version hợp lệ, không chỉ là lời báo của client.
            10. Record verified source + processing intent/outbox theo recovery contract.
            11. Relay/admission tạo job stable identity sau durable state.

            Encode rồi publish manifest

            1. Claim source/pipeline version; retry không thay source dưới cùng job ID.
            2. Đọc đúng source object version đã verify.
            3. Trả source cho probe/parallel encode trong resource budget.
            4. Ghi segments và derivatives vào immutable staging version; validate checksum/decode/timing.
            5. Artifact đã có và đọc được trước khi manifest tham chiếu.
            6. Kiểm required ladder, validation và policy/rights gates cho generation hiện tại.
            7. Gate pass; nếu pending/blocked thì không publish dù encode xong.
            8. Ghi manifest immutable chỉ trỏ tới assets hợp lệ.
            9. Manifest version đã sẵn sàng.
            10. CAS published pointer/READY theo generation, không ghi đè DELETED/BLOCKED từ job cũ.

            Authorize và xem segment qua CDN

            1. Yêu cầu playback với principal/device/context.
            2. Đọc desired/publication state và quyền theo policy.
            3. Trả manifest version được phép, không tự xem PROCESSING là READY.
            4. Cấp manifest/session access phù hợp; expiry và revoke semantics rõ.
            5. Player yêu cầu manifest/playlist/segment; mỗi resource cần đúng access control.
            6. Cache hit hợp lệ trả bytes; ABR quyết định request segment tiếp theo.

            CDN miss và origin fill

            1. Segment đã publish nhưng edge chưa có.
            2. Sau authorization/cache-key processing, shield/origin request đọc đúng immutable asset.
            3. Trả segment; cache theo policy. Coalescing là cấu hình, không phải mọi miss đều tự gộp.
            4. Trả bytes; player quan sát download time và buffer, không chỉ API latency.

            5. Resumable upload không chỉ là chia file

            Vòng đời upload có thể resume

            1. Authorize và tạo session

              Owner, key, expected size và allowed operations.

            2. Upload các part

              Persist progress, retry phần lỗi và refresh scoped URL.

            3. Verify rồi enqueue

              Complete storage, pin source version, durable processing intent.

            Một sự cố mạng chỉ nên retry phần cần thiết; success của từng part không phải READY.

            Giữ session ID, part number/checksum và object identity để resume sau app restart. Retry phần lỗi thay vì cả file, nhưng concurrency và part size phải phù hợp mạng/storage limits. Dùng lifecycle/abort cho multipart bỏ dở và job cleanup có ownership; upload URL hết hạn không có nghĩa storage tự xóa mọi part đã gửi. Không coi part ETag là universal full-file integrity proof.

            Source được verify bằng exact object/version để signed URL cũ hoặc late event không thay file của job đang encode. Nếu object hoàn tất nhưng DB update mất, reconciliation phải tạo/recover processing intent đúng identity. Direct upload không miễn validate ownership, quota, file/container và malicious metadata; probe/decoder chạy trong resource sandbox.

            6. DAG, retry task và publish progressive

            Probe nguồn, validate container/stream, encode các compatible rendition/codec rồi package manifest/segments. Task identity gồm source version, encode parameters và pipeline version. Output staging immutable hoặc mỗi attempt có namespace riêng; chọn winner/manifest pointer theo CAS, không cho hai worker ghi khác bytes vào một segment đã publish. Retry task không nhất thiết bit-for-bit deterministic ở mọi encoder.

            Parallel segment encoding cần keyframe/GOP, timebase, audio sync và packaging compatibility; chia file tại byte offset bất kỳ không bảo đảm decode/seam đúng. Parallelism giảm wall time khi đủ capacity nhưng có scheduler/I/O/overlap overhead, không chứng minh total compute không đổi. Progressive publish có thể đưa minimum validated ladder lên trước và thêm high rendition sau; mọi mandatory policy/rights gate vẫn áp dụng.

            Không mặc định xử lý từ S3 multipart part đang upload: final object thường chỉ sẵn sàng theo completion semantics. Muốn encode trước khi upload xong cần ingest/fragment/container format hỗ trợ và protocol riêng, không chỉ bật một worker sớm hơn. Đo bottleneck trước: ingest, probe, queue, encode, package và publication có thể là các giới hạn khác nhau.

            7. Manifest phải tham chiếu asset đã sẵn sàng

            Đầu tiên ghi segments/init/audio/caption cần thiết, validate availability/integrity/timing, rồi manifest immutable; cuối cùng đổi metadata pointer/READY bằng generation guard. Nếu đổi READY trước khi segments có thì viewer gặp 404; nếu job cũ publish sau takedown thì content có thể sống lại. Model desired state + processing generation ngăn stale completion ghi đè BLOCKED/DELETED.

            Khi thêm rendition, tạo manifest version mới chỉ trỏ tới asset hợp lệ và update pointer có điều kiện. Giữ old assets trong drain/cache lifetime phù hợp để player đang xem không hỏng. Metadata DB, object storage và cache không tự có một transaction toàn cục; reconciliation, manifest validation và rollout/rollback phải được test.

            8. Codec và ladder là tối ưu có điều kiện

            Codec choice phụ thuộc device/profile/level, hardware decode, quality target, encode latency và storage/egress. H.264, VP9 và AV1 không có một tỷ lệ tiết kiệm byte cố định cho mọi nội dung/encoder. Negotiate compatible playback thay vì hứa một codec universal; giữ fallback cần thiết mà không tạo mọi tổ hợp cho mọi upload.

            Per-title/per-shot ladder tối ưu bitrate-quality theo complexity: animation, talking-head và sports khác nhau. Metric như VMAF hỗ trợ quality evaluation nhưng không thay mọi human/device/latency concern. Popular content có thể đáng re-encode codec đắt để giảm byte ở nhiều view; long tail có thể dùng cheaper initial ladder. Quyết định từ measured quality, expected watch time và resource/cost budget, không chỉ view-count threshold bất biến.

            9. ABR chọn quality bằng estimate và buffer

            HLS/DASH phân phối media qua playlist/manifest và segments hoặc byte ranges phù hợp. Player chỉ chọn rendition codec/resolution/device hỗ trợ và chuyển ở boundary tương thích. Throughput estimate là quá khứ, không biết trước mạng sắp giảm; buffer mua thời gian phản ứng. Highest bitrate không luôn tối đa trải nghiệm nếu startup/stall tăng.

            ABR policy tối ưu trade-off quality, startup, stall và switching; heuristic trong lab không phải production player. Segment ngắn có thể phản ứng nhanh nhưng tăng request/container overhead; prefetch giảm startup khi dự đoán đúng và có thể lãng phí byte/data khi đoán sai. Buffer có maximum/pacing ở player thật, còn replay dưới đây chỉ làm rõ phép tính download và drain.

            10. CDN, shield và cache key

            Immutable asset version giúp cache lâu và rollback pointer an toàn hơn overwrite segment cùng URL. Edge → shield → origin giảm repeated cold fills khi cache-key/coalescing đúng, không bảo đảm mọi concurrent miss tự thành một request. Watch request hit ratio và byte hit ratio riêng; manifest nhỏ hit nhiều không chứng minh segment bytes đã được cache tốt.

            Query string/token hoặc vary header có thể làm cache fragmentation. Không đơn giản xóa auth parameter khỏi key rồi bypass quyền: edge phải authorize đúng mọi request theo access design, sau đó mới reuse media bytes chung nếu hợp lệ. Cold cache, new release, multi-CDN failover và origin outage cần capacity/headroom và request-collapse/backoff riêng.

            11. Playback authorization, expiry và takedown

            Kiểm visibility/entitlement tại playback session và enforce access trên manifest, playlists, segments, caption/audio và key/license resources cần bảo vệ. Signed URL/cookie có scope/expiry không tự thu hồi bytes đã tải; browser cache cũng không bị xóa chỉ vì metadata đổi. Chọn revoke/takedown delay rõ và phối hợp edge policy, short-lived access, purge hoặc key/license policy phù hợp.

            CDN authorization có thể được kiểm trước cache hit tùy cấu hình; không coi cache hit mặc định là public hay mặc định đã đúng quyền. DRM/content encryption khác access token: cần key/license lifecycle và device capabilities, cũng không bảo đảm người dùng không thể quay màn hình. Moderation/rights block phải chặn new publication và access theo policy, kể cả job cũ còn chạy.

            12. Schema và view events

            Video metadata gồm owner/visibility, desired state, verified source version, generation/pipeline version, rendition capabilities, manifest pointer và timestamps. Task/attempt records có stage, artifact/checksum và error/retry reason; giữ failed attempt riêng thay vì overwrite mọi evidence. Source/encoded asset retention và deletion cần lifecycle cho orphan, incomplete upload, unpublished derivative và old published version.

            Định nghĩa view: play request, first frame hay watched-time threshold? QoE telemetry và product view count là hai loại signal khác nhau; replay/bot/dedup identity cần policy. Async event aggregation tránh hot metadata row ở quy mô lớn, nhưng count exact/auditable có thể cần ledger mạnh hơn. Ở scale nhỏ atomic counter có thể đủ; không biến một tối ưu scale thành quy tắc cấm mọi UPDATE.

            13. Failure matrix của video

            Tách upload availability, time-to-playable và playback availability. Processing chậm không nên làm published content cũ ngừng xem; metadata/control outage có thể dùng bounded cached authorized state nếu contract cho phép. Player fallback đổi CDN/quality phải giữ asset/version/access compatibility; origin không đủ sức nhận toàn bộ viewer traffic khi edge cold.

            14. Đo QoE và chọn đòn bẩy tối ưu

            Theo dõi upload completion/abandonment, stage queue age, task retry/waste, time-to-minimum-playable và time-to-full-ladder. Playback đo click-to-first-frame, rebuffer duration/ratio, quality switches, error và delivered bitrate theo device/codec/ISP/region/CDN. Một API response nhanh không chứng minh player decode hoặc first frame nhanh.

            Cost model tách ingest/raw/encoded storage, encode/re-encode compute, CDN viewer bytes và origin fills. Bill tăng không đồng nghĩa traffic view tăng: watch duration, bitrate, geographic mix, cache fragmentation hoặc provider pricing/contract có thể đổi. So sánh cùng cohort/QoE trước khi giảm bitrate; multi-CDN route dựa real-user metrics cần kiểm bias và fallback capacity.

            15. Câu hỏi phỏng vấn và reasoning cho video

            Đi qua upload session tới durable source, một task retry, publication pointer và một segment download. Sau đó thay đổi mạng hoặc làm hỏng high rendition để kiểm tra guarantee.

            Video 4K encode chậm: thêm worker có luôn giảm time-to-publish không?

            Không nếu bottleneck là ingest, serial probe/package hoặc một task không chia được. Profile từng stage, parallelize theo boundary decode/encode đúng, ưu tiên minimum compatible ladder và gates. Progressive publish có thể giảm first-playable time nhưng không bỏ validation hay tự giảm total compute.

            Chỉ metadata READY trước rồi upload segment sau để publish nhanh được không?

            Không theo contract playable. Viewer có thể lấy manifest và gặp missing assets. Ghi/verify artifacts trước, manifest immutable sau, cuối cùng CAS pointer/READY theo generation. Job cũ không được overwrite delete/block.

            CDN byte hit 95% thì viewer egress chỉ còn 5% đúng không?

            Không. Viewer vẫn nhận toàn bộ media bytes qua CDN; khoảng 5% là miss bytes tới origin trong mô hình đơn giản. Request hit khác byte hit. Cache/shield giảm origin work, còn bitrate/watch time/codec ảnh hưởng viewer bytes.

            ABR lấy bitrate bằng network speed estimate có hết stall không?

            Không. Estimate nhìn về quá khứ; bandwidth có thể drop, audio/overhead/RTT và buffer cũng tác động. Safety margin/buffer-aware rules giúp nhưng không bảo đảm, nhất là khi network thấp hơn rendition nhỏ nhất. Đo startup, rebuffer và quality theo cohort.

            Có thể encode S3 multipart parts trước khi complete như file hoàn chỉnh không?

            Không mặc định. Object availability và media container có semantics riêng; partial upload có thể thiếu metadata/index cần decode. Muốn early processing cần ingestion/container/protocol hỗ trợ và validation riêng. Baseline chờ verified final source rồi enqueue.

            Sử dụng AV1 có luôn giảm cost so với H.264 không?

            Không. Kết quả phụ thuộc content/quality/encoder, encode cost, watch count, device decode và fallback. Đo byte tiết kiệm trên compatible views so với compute/storage/energy thêm; long-tail và high-popularity title có quyết định khác nhau.

            Signed URL hết hạn có thu hồi được mọi segment user đã tải không?

            Không. Nó kiểm soát request/access theo provider policy, không xóa bytes đã nhận hoặc browser cache. Takedown/revocation có delay và cần enforce trên resource/key/license phù hợp; metadata đổi một mình không đủ.

            View count tăng ít nhưng CDN bill tăng mạnh, tìm gì trước?

            Tách byte × unit price và origin fill. Kiểm watch seconds/view, average bitrate, codec/device mix, region/ISP mix, cache-key fragmentation, shield và pricing contract. Đừng chỉ nhìn view count hoặc request hit ratio rồi kết luận.
