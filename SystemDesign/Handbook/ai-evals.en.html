Evaluation & Quality Gates: measure quality and understand uncertainty

Build versioned evaluation sets, select failure-specific metrics, calibrate model judges, compare paired outcomes and qualify per-slice evidence before canaries. Explore bootstrap, judge bias and release evidence interactively.

From quality requirements to maintainable evidence

  1. Define acceptance

    Define outcomes, severity, slices and exclusions.

  2. Version cases

    Version representative samples, labels/rubrics and holdouts.

  3. Run / score

    Match candidate/baseline runs with code checks and calibrated judges.

  4. Qualify evidence

    Review intervals, slices and missing evidence.

  5. Expose / learn

    Bound exposure and learn from outcomes, rollback and incidents.

Each step addresses a different question: what to measure, whom it represents, how reliable the measurement is and when to stop rollout.

  • Evaluation suites are bounded operational acceptance contracts rather than complete product intent or proof of no unknown failures.
  • Version datasets, splits, rubrics and dependencies; never silently remove timeouts or errors from denominators.
  • Judge agreement, answer-order consistency and correctness are different quantities.
  • Paired bootstrap preserves matched cases, while clustering, sampling bias and degenerate samples require additional treatment.
  • Higher averages do not offset severe disclosures or critical-slice regressions.
  • Offline qualification permits controlled online trials, with product outcomes, guardrails and rollback still required.

1. What does an evaluation suite establish?

Task outcome

  • Complete tasks correctly using available evidence and allowed actions.
  • Separate correctness, helpfulness and preference when needed.

Hard constraint

  • Prevent unauthorized disclosures and effects.
  • Do not offset severity with aggregate scores.

Operational constraint

  • Define latency, availability, cost and fallbacks.
  • Use matched task mixes and denominators.

A support assistant can sound fluent while misapplying refund policy, disclosing another tenant’s data or failing to escalate when evidence is missing. Define tasks, users, available evidence, permitted actions, refusal/escalation rules and error severity. Give important requirements owned cases, metrics, rubrics or runtime invariants rather than treating fluency as acceptance.

A suite operationalizes part of a product specification but has finite coverage, imperfect labels and blind spots. Passing does not prove universal correctness. Unit/integration tests, threat modeling, human research and runtime authorization retain distinct roles; benign prompt tests do not establish resistance to adversarial inputs.

2. Build datasets with coverage, labels and protected holdouts

Combine authorized production samples, expert cases, incident regressions and reviewed synthetic data. Random traffic sampling helps characterize common workloads; targeted hard cases expose weaknesses without automatically representing production prevalence. Report these purposes separately or use predefined weights. Adversarial challenge sets do not directly estimate population failure rates.

Version identities, task/context snapshots, labels or acceptable-answer criteria, slices, provenance, owners and permissions. References can be wrong or stale: adjudicate disagreements and preserve checkable rationales. Open-ended tasks may require multiple valid answers or rubric dimensions instead of one literal string.

Split by entities, conversations or time when dependence requires it, deduplicating near-duplicates first. Govern finalist access to holdouts rather than repeatedly tuning against their detailed failures. Refresh for distribution changes while preserving bridge evaluations that distinguish system improvements from easier datasets.

3. Match metrics to failures rather than novelty

Code / execution

  • Concrete checks for machine-verifiable contracts.
  • Finite tests do not establish all behavior.

References / evidence

  • Use facts, retrieval labels and acceptable answers.
  • Validate references and legitimate alternatives.

Model / human rubric

  • Separate factuality, relevance, tone and policy.
  • Calibrate, blind review and preserve disagreement.

Use deterministic checks for contracts code can verify: parsing, schemas, enums, arithmetic, unit tests, preconditions and effects. Valid schemas do not establish semantic correctness, and existing citation IDs do not establish support. Do not substitute model judges for authorization or suitable trusted computations.

Reference-based checks can help well-defined tasks while penalizing valid paraphrases or rewarding incorrect references. Model rubrics add flexibility with grader error; humans add expertise with disagreement and cost. Combine by risk, report dimensions separately and justify any aggregate weights without blending away hard constraints.

4. Evaluate RAG and agents at multiple boundaries

Separate diagnosis instead of one opaque score

  1. Retrieve

    Did relevant evidence enter the candidate set?

  2. Pack

    Did authorized evidence survive packing?

  3. Generate / act

    Are claims, citations, tools and effects correct?

  4. Resolve

    Was the task completed, declined or escalated appropriately?

Give each boundary its own inputs, outputs and metrics.

Evidence recall needs relevance labels and explicit denominators; ANN recall against exact vector neighbors measures a different quantity. Context metrics depend on chunk/claim definitions. Evaluate rewriting, candidates, reranking and packing separately: evidence retrieved but omitted from the final prompt can still cause failure.

Generation requires correctness, support, attribution, completeness and appropriate abstention. Faithfulness to incorrect context does not establish truth, while lucky correctness does not establish grounding. Agents also need tool-argument, authorization, effect-count, budget, termination and recovery checks; polished final prose can conceal incorrect effects.

5. Design model judges with rubrics and calibration

Provide task context, authorized evidence, scoring dimensions, anchored examples, tie/unknown rules and structured verdicts. Pin available judge revisions, rubric/prompts, settings, references and parsers. Judge timeouts and parsing failures must not be silently dropped or casually conflated with candidate errors; retain grading coverage and failures.

Calibrate against blinded human labels by task, language and risk. Inspect agreement, systematic errors and severe false acceptance. High aggregate agreement may reflect easy-case imbalance; examine label/slice confusion patterns, reviewer consistency and adjudication. Strong judges are not infallible, and calibration need not transfer to new domains.

Answers and retrieved material are untrusted grader inputs. Separate data from grading authority, restrict tools/network access and test grader injection. Respect data policy before using external graders. Adding an instruction to ignore embedded instructions does not prove isolation.

6. Position, verbosity and style bias: swapping is insufficient

Judges can favor positions, length or familiar styles depending on task/model/rubric. Blind identities, balance orders, inspect controlled cases and calibrate against humans. Repeated preference establishes consistency under those measurements rather than correctness; humans and models can agree on incorrect answers.

Record conflicting order judgments as unresolved under a declared adjudication policy. A protocol tie is not evidence of equal answer quality. Consistent-only win rates change denominators: also report consistent B, consistent A and unresolved outcomes over all pairs. Dropping disagreement can introduce selection bias and does not remove all bias.

7. Trace an evaluation platform

Pin candidates, baselines, datasets, environments, graders, sampling settings and code. Preserve item outcomes before aggregation to recover exact failures. Seeds do not universally guarantee bitwise reproduction across backends or revisions; preserve actual outputs and distinguish generation variability from case-sampling uncertainty.

Which evidence boundaries does a change cross?

Component map; the complete ordered request paths are explained below.

Run baseline and candidate

  1. Freeze manifests and comparisons before inspecting scores.
  2. Load approved cases, labels/slices and denominators.
  3. Run matched cases under bounded retries/timeouts and sandboxing.
  4. Record failures as well as successful outputs.
  5. Grade with suitable metrics while preserving revisions.
  6. Persist item outcomes, judge versions and costs.

Calibrate judges for the task

  1. Sample task slices and collect blinded rubric-based labels.
  2. Judge pinned answer pairs in both orders.
  3. Review agreement, systematic disagreement and consequential misgrading.
  4. Version adjudications/rubrics while retaining unresolved cases.

Decide regression gates

  1. Aggregate paired differences and slices with explicit denominators.
  2. Run finalists under controlled access to independent holdouts.
  3. Missing or failed runs do not become passes; review uncertainty.
  4. Blocked or insufficient evidence requires follow-up before rollout.

Canary after offline qualification

  1. Expose qualified candidates under declared gates and rollback plans.
  2. Observe windowed product outcomes, severity, latency and cost.
  3. Stop or roll back on guardrail failures; canaries are not automatic causal A/B evidence.

Turn incidents into regression coverage

  1. Triage failures using minimal authorized traces and owners.
  2. Review labels, duplication, data scope and stable identities before admission.
  3. Rerun relevant regressions and preserved baselines.
  4. Refresh holdouts under governance without leaking tuning feedback.

8. Pair comparisons and retain both gains and regressions

For case i, let binary outcomes A_i and B_i define d_i=B_i−A_i in {−1,0,+1}. Mean difference is (gains−losses)/n. Identical marginal pass rates can arise from very different discordance patterns and uncertainty. Pairing controls some between-input variation without correcting biased labels or sampling.

For 100 cases with 50 shared passes, 12 gains, 8 losses and 30 shared failures, baseline is 58%, candidate 62% and difference +4 percentage points. This differs from a roughly 6.9% relative improvement. Predefine timeouts, retries, refusals, incomplete outputs and non-applicable cases; unequal silent filtering breaks matched comparison.

9. Interpret intervals without overclaiming

Paired percentile bootstrap resamples original case indices with replacement, using identical indices for both versions before taking difference quantiles. Nonparametric does not mean assumption-free: sampling units, representativeness and variation matter. Requests clustered by user/document or repeated per case may need cluster or hierarchical procedures.

A frequentist 95% interval describes repeated-procedure coverage under assumptions, not a post-data probability for a fixed parameter. Including zero does not establish equivalence, and excluding it does not establish practical value. Predefine non-inferiority margins and suitable one-sided methods rather than treating nonsignificance as proof of no regression.

A single rate of 70/100 has an approximately [60.4%,78.1%] Wilson 95% interval. With no observed discordance, paired percentile bootstrap can yield [0,0], reflecting sample degeneracy rather than universal equivalence. Boundaries and rare events require suitable additional methods and evidence.

10. Sample size, power and adaptive comparisons

No universal sample count or score gain settles adequacy. Precision and power depend on rates, paired discordance, relevant effect sizes, clustering, grader reliability, tails and error budgets. More easy examples cannot replace critical-slice coverage; design analyses or simulations with defensible assumptions and sensitivity checks.

Selecting the best of many prompts on a small development set introduces selection optimism. Separate exploration from confirmation, protect holdouts, predeclare primary metrics/gates and account for multiple comparisons. A post-selection bootstrap interval does not automatically correct adaptive overfitting, and repeated unplanned A/B peeking can invalidate inference.

11. Gate regressions, hard failures and missing evidence

Gate configurations need definitions, directions, units, scopes, evidence requirements, uncertainty rules, baselines, severity and owners. Helpfulness does not offset unauthorized disclosure or effects. Quality non-inferiority can compare paired lower bounds to a predefined margin, while latency/cost require their own windows and denominators. Teaching thresholds are not universal standards.

Missing outcomes, grader errors and insufficient slices require explicit policy states rather than default passes. Zero observed privacy failures do not imply zero population risk. Canary decisions still require residual-risk review, rollback and operational controls.

12. Shadow, canary and A/B answer different questions

Controlled exposure

  1. Shadow

    Hide candidate outputs and prevent real tool commits.

  2. Bounded canary

    Bound traffic, monitor severity and support rollback.

  3. Experiment

    Use randomization and planned analysis for causal questions.

  4. Maintain

    Track drift, incidents and suite refreshes.

Give every step stop rules, owners and data policies.

Shadowing evaluates live inputs without serving candidate outputs, yet still incurs compute and data exposure and must control effects. Canaries bound exposure and aid rollback without automatically establishing causality. A/B experiments require appropriate assignment units, stable exposure, sufficient duration and attention to interference.

Track task resolution, appropriate escalation and user outcomes alongside disclosure, harmful effects, latency tails and cost. Copying, regeneration, editing and abandonment require interpretation; users can copy incorrect answers or regenerate for style. Voluntary feedback is selected. Combine expert sampling, appropriate experiments and trace diagnosis rather than treating clicks as correctness.

13. Traces enable diagnosis without becoming ground truth

Useful traces link run/case/scope, input revisions, rewrites, retrieved IDs/scores, packed evidence, configuration hashes, attempts/effects, latency, usage and outcomes. They need not contain secrets or private reasoning. Apply access controls, minimization, retention and deletion/audit policies; hashing identities does not automatically anonymize data.

Traces can locate missing packed evidence without proving a unique cause. Retrieval, permissions and labels can fail together. Preserve minimal versioned sandbox fixtures and review incidents before turning complaints into labels. Monitor traffic and provider behavior rather than relying only on model-version strings.

15. Maintain evaluations as owned products

Assign ownership, review schedules and histories to datasets, rubrics and graders. Bridge label changes to distinguish benchmark changes from system changes. Budget model calls, humans, storage and triage. Risk-based grading samples need explicit sampling rules and coverage; do not compare full-corpus results to selected successful cases without disclosure.

Feed reviewed production failures and drift into regressions and governed holdout refresh. Restrict holdout/trace access and sandbox runners under quotas. Release owners need limitations and missing evidence alongside scores rather than a single green CI badge.

16. Practice evaluation decisions

A candidate gains 3 points on 150 cases: ship?

Inspect paired uncertainty, sampling units, slices and practical margins rather than assuming significance or noise. Check graders, leakage, operations, severity and holdouts, then use qualified bounded exposure.

Why can both answer orders prefer B incorrectly?

Consistency differs from correctness: content errors, style bias or injection can persist across orders. Calibrate against blinded task evidence and retain unresolved denominators.

Does dropping conflicting pairs solve bias?

No guarantee: judge-selected subsets change denominators and can be biased. Report all-pair consistent and unresolved mass with adjudication and human calibration.

What if average improves 6 pp but enterprise falls 30 pp?

Majority slices can dominate averages. Apply critical-slice policies, inspect evidence and diagnose rather than offsetting the regression or quietly removing users.

Does a [0,0] bootstrap interval establish equivalence?

No: resampling unvarying observed differences cannot create unseen failures. Use representative coverage and suitable boundary/equivalence methods.

Does high faithfulness establish correctness?

Not with incorrect or stale context. Existing citation IDs do not establish entailment. Separate relevance, freshness, support, correctness and abstention.

Is shadowing risk-free?

No: live data, costs and possible tool effects remain. Sandbox writes, enforce data policies/quotas and distinguish hidden-output checks from user outcomes.

What if 10% of cases time out but scored cases perform well?

Report coverage and end-to-end denominators. Distinguish candidate, infrastructure and grader failures, retain suitable attempt records and declare missing matched evidence explicitly.

These open questions connect terminology to state, assumptions and failure boundaries. Try an example from your own work before comparing the explanation.

Which biases and failures need checks when using an LLM judge?

Judges can favor position, length, style, model families or persuasive but false answers; rubric parsing can fail too. Version the setup, blind identities, counterbalance order and calibrate against domain experts. Do not silently discard disagreements to improve reported scores; retain unknowns, errors and timeouts with explicit denominators.

Prefer trusted deterministic checks for arithmetic, schemas, authorization and execution contracts. Model grading helps open-ended dimensions without replacing access control or proving correctness. Report slices, paired uncertainty and severe regressions before aggregates. Human labels also need adjudication, and protected holdouts help prevent repeated tuning against evaluation details.
