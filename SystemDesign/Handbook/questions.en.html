4. Example: does caching solve read load?

Caching can reduce database reads when reuse is sufficient and representations remain valid for callers. Establish allowed staleness, authorization scope, value sizes, hit distributions and failure behavior. It may not help unique reads, rapidly changing data or an independent authorization bottleneck.

An idealized 10000 eligible reads/s with 90% hits gives 1000 cache misses/s, excluding writes, retries, refreshes, cold starts, skew and bypasses. If the cache fails, do not send all 10000 reads/s to a database safely handling only 2000; bound fills, coalesce work and specify acceptable degradation.

Private data may require fail-closed behavior or an independently authorized fallback. Stale public metadata and stale authorization have different risks. Measure load and freshness by slice and test read/write races and cold starts. Reconsider the choice when reuse falls, freshness tightens or operational burden outweighs savings.

6. Use numbers with defensible assumptions

Separate observed inputs, design assumptions and model outputs. Daily operations divided by86400 gives average rate rather than peak. Mean concurrency follows arrival rate times mean time under appropriate boundaries, populations and observation conditions; p99 is not a direct substitute. Fan-out, retries and bytes can dominate before edge request counts.

If a latency benchmark is unknown, name the operation and how it would be measured in the target environment. Hardware, locality, payload, cache state and contention matter. A defensible range with assumptions and validation is more useful than a memorized number with incorrect units. Distinguish decimal GB/TB from binary GiB/TiB.

7. Self-assess without false certainty

Known is a personal reminder, not expert verification. Use it after explaining the mechanism, an example and its key limitation unaided. If only technology names come to mind or a failure boundary is missing, mark review and revisit the lesson. Clear a rating when changed requirements expose a gap.

Marks are shared with Notes & Interview and Study Desk but do not change Again/Hard/Good/Easy schedules. Daily Review has separate intervals and Mock Interview stores separate notes and history. Rating a question should preserve note bookmarks, chapter progress and other practice data; writes target only selected identities and reread storage immediately.

8. Local storage, multiple tabs and recovery

Marks live in the current browser origin without an account. Switching between localhost and GitHub Pages, profiles or browsers does not transfer them automatically. Study Desk exports and imports marks; Mock and Daily Review files have separate scopes. Inspect exported files before sharing personal study data.

Malformed existing storage disables writes rather than silently replacing it with an empty state. Practice remains available; export the raw file before intentional repair. Other-tab events refresh marks and read-before-write reduces stale overwrites, but localStorage offers no multi-tab transaction or compare-and-swap guarantee.

9. A focused fifteen-minute practice routine

Choose one topic or a manageable set rather than sweeping the library. Attempt answers, then record a gap, a counterexample and a lesson to revisit. Complex questions deserve time; a few well-explained mechanisms are more useful than rapid recognition.

Finish with a checkable improvement: reconstruct a cache race, run an isolation schedule, recalculate egress or explain permission authority. Return through review marks or Daily Review. A large known count does not establish performance on unfamiliar design interviews.

10. Questions about effective practice

Should two questions about caching be merged?

Shared keywords are insufficient. Hit ratio can test costs, stale fills test ordering, and private caches test permission boundaries. Merge only complete duplicates in both languages while retaining origins; distinct contexts need their own reasoning or lesson links.

Does marking review remove the active flashcard?

No. Live filters reflect new marks while the active session retains its identity snapshot until explicitly replaced. You can finish the answer, clear a rating or navigate deliberately. This is UI behavior, not a spaced-repetition algorithm, and due dates are unchanged.

Why can a search hit fail to establish unaided recall?

Search includes answers and follow-ups, providing cues absent from an interview. Recognition, recall and application differ. Read lists to learn, use hidden-answer cards for explanation, then variations or mock sessions to test assumptions and design judgment.

Should invalid local data be silently cleared?

No. Disable writes, preserve raw data and allow intentional recovery. Parsed JSON still needs shape validation before array updates. Local storage is not cloud backup; exports need the right scope and edits must preserve unrelated study data.
