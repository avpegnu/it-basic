RAG Systems: retrieve evidence, preserve access and ground answers

Build ingestion/query pipelines with chunking, compatible embeddings, hybrid fusion, ANN, reranking, freshness and citation checks while separating retrieval quality, answer quality and access control.

Two pipelines and one evidence contract

  1. Ingest

    Parse/chunk with provenance, revisions and publication guards.

  2. Retrieve

    Retrieve eligible lexical/vector candidates and fuse ranks.

  3. Select evidence

    Fetch fresh evidence, rerank and budget diverse spans.

  4. Answer and verify

    Check claims/references, abstention and access boundaries.

Measure each layer to address causes rather than only switching to larger models.

  • RAG supplies evidence rather than automatically making generations correct.
  • Ingestion, candidates, reranking, packing and generation need separate failure measurements.
  • Hybrid fusion can combine complementary retrievers without universal gains; reranking cannot recover absent candidates.
  • ANN neighbor recall and annotated relevance recall are different metrics.
  • Permissions/deletes require exposure policies, publication guards and scoped caches; index metadata can be stale.
  • Citation identities aid tracing but do not replace support, freshness and abstention checks.

1. RAG combines retrieval and generation rather than replacing a database

RAG retrieves external information at query time for a generator. Sources can include private documents, catalogs or changing records. Retrieval can miss, and generators can misinterpret, ignore or embellish evidence. Diagnose failures rather than universally attributing most errors to retrieval.

Tasks may require several passages jointly; one relevant chunk does not cover every subquestion. Separate source coverage, ingestion completeness, candidate recall, packed evidence and answer quality. Structured records can be better served by deterministic SQL/APIs than text-neighbor search.

2. Ingestion preserves structure, identity and revisions

Ingestion includes discovery, snapshots/change feeds, parsing/OCR, normalization, chunking, embeddings and indexing. Preserve document generations, spans, parser/chunker/embedding versions, timestamps, access metadata and checksums. Source positions support citations and debugging; mutable identities alone cannot distinguish historical content.

Flattened PDFs/tables/code/headings can lose meaning. Detect parsing failures, language issues, repeated headers and missing pages before publication. Retried jobs need stable identities and conditional publication so late work cannot overwrite updated/deleted sources. Staging success does not automatically establish query readiness.

3. Chunking changes coverage and context costs

Fixed windows

  • Simple budgets with explicit stride/overlap.
  • Test boundaries and duplicated evidence.

Structural units

  • Preserve headings, code and tables when parsing supports them.
  • Bound large sections and define fallbacks.

Semantic or parent expansion

  • Can improve task-specific coherence/coverage.
  • Measure costs, version stability and context budgets.

Fixed token windows are easy to budget but split structure; structural boundaries preserve locality with good parsing; semantic splits add computation and version sensitivity. Small chunks can omit conditions, while large chunks dilute relevance and consume context. Small retrieval units can expand into authorized parent/surrounding spans under bounds.

Overlap helps some boundary misses without guaranteeing containment, while creating duplicates and extra storage. A10,000-token document with 500-token windows and 400-token stride produces 25 windows when stopping after full coverage, totaling 12,400 serialized tokens with a 400-token final window. Use explicit tokenizer/structure rules rather than confusing words and tokens.

Headers can supply titles/sections/paths or generated summaries before indexing. Distinguish authoritative metadata from generated context, which can introduce false cues. Preserve raw spans for citations and version representations when headers change.

4. Embedding spaces, metrics and encoder profiles

Compatible profiles before neighbor search

  1. Profile

    Pin query/document templates, encoder pairs, truncation and versions.

  2. Represent

    Use dimensions and normalization required by the model.

  3. Compare

    Apply metrics, eligibility and exact/approximate search.

  4. Evaluate

    Separate neighbor recall from relevance and answer support.

Metric equivalence depends on explicit assumptions.

Embeddings represent inputs under a training objective; proximity need not equal answer relevance. Queries/documents can use different prefixes or jointly trained encoders. Pin compatible profiles, dimensions, normalization, truncation and metrics rather than mixing equal-dimensional but incompatible vectors.

Cosine equals dot product for unit-normalized vectors; their squared L 2 distance is 2−2dot, giving equivalent ordering under those assumptions. Handle zero vectors and magnitude-sensitive unnormalized products explicitly. Similarity is not automatically a probability or a globally calibrated threshold.

Incompatible representations need separate generations and matching query encoders, backfills and change catch-up. Evaluate relevance, answers, access, freshness and costs before manifest cutover with rollback. Compatibility must be designed/validated rather than inferred from family names; compatible changes need not always rebuild every vector.

5. Ingestion and queries follow distinct paths

Ingestion emphasizes completeness/publication while queries seek eligible relevant evidence within latency budgets. Rewriting, retrieval, fusion, fresh fetching, reranking and assembly are separate stages rather than one vector query returning a final answer. The diagram separates source/policy authority from derived indexes and model confidence.

Indexes supply candidates; permissions and evidence decide what may be used

Component map; the complete ordered request paths are explained below.

Ingest into published indexes

  1. Read stable content generations and access/deletion metadata.
  2. Embed bounded structured chunks under pinned profiles.
  3. Write staged vectors/metadata under generations.
  4. Index lexical fields/identifiers using matching chunk identities.
  5. Validate readiness and reject obsolete builders before publishing.

Authorized hybrid retrieval

  1. Validate scopes and form bounded standalone/subqueries when useful.
  2. Resolve trusted identity/current policies rather than model-supplied ACLs.
  3. Retrieve eligible lexical candidates with pinned analyzers.
  4. Use compatible query vectors/metrics and eligible filtering.
  5. Merge IDs, fetch fresh content and authorize before exposing text.

Turn candidates into cited answers

  1. Select bounded relevant spans without treating scores as factual proof.
  2. Provide versioned evidence identities and conflict/unknown rules.
  3. Enforce the intended access boundary for previews/references.
  4. Return answers/abstention, valid references and freshness metadata.

Delete or revoke access

  1. Record authoritative deletions/revocations and invalidate exposure decisions.
  2. Advance relevant generation/policy barriers against stale publication.
  3. Apply tombstones/filter updates and schedule cleanup.
  4. Remove/update lexical entries and caches under freshness contracts.
  5. Recheck exposure while index metadata catches up.

Change embedding profiles

  1. Build a new generation from stable snapshots plus incremental changes.
  2. Use new compatible profiles without mixing unverified vector spaces.
  3. Populate a separate generation and track completeness/failures.
  4. Compare retrieval/task quality, freshness and costs before manifest cutover.
  5. Pin matching query encoders/index generations and retain rollback.

6. Teaching APIs preserve evidence and permission scopes

These are internal teaching contracts rather than vendor endpoints. Servers bind verified identity/scopes instead of trusting caller-supplied group claims. Results pin index/content/embedding generations, while answers retain versioned evidence references for tracing and access-checked previews.

    7. Lexical, semantic and rank fusion

    Lexical retrieval preserves term/identifier/phrase signals, with BM25 frequency saturation, rarity and length normalization. Semantic search can match paraphrases yet miss rare codes or retrieve nearby but unhelpful content. Evaluate identifiers, analyzers and languages rather than assuming universal strengths or weaknesses.

    A common BM25 form sums IDF(t)×f(k 1+1)/(f+k 1(1−b+b·len/avgLen)), with variant scoring/IDF choices. One nonnegative IDF isln(1+(N−df+0.5)/(df+0.5)). Raw lexical/vector sums need scale handling; RRF uses ranks through 1/(k+rank). Sixty is a conventional starting value rather than a universal optimum, and duplicate list entries must not inflate votes.

    Fusion can improve or worsen individual queries. It cannot invent candidates absent from all lists; reranking only reorders candidates. Deeper lists can improve coverage at additional work/noise. Track retriever-specific relevance and latency to locate weaknesses.

    rank_A(OPS) = 2, rank_B(OPS) = 3, k = 60
RRF(OPS) = 1/(60+2) + 1/(60+3) ≈ 0.032002
// One-based ranks; absent list contributes zero.
// This score is not an answer-correctness probability.

    8. Explore candidate ceilings, fusion and filter order

    The lab declares two lists and relevance labels to isolate fusion/selection rather than running retrieval models. Early-filtered hybrid depth 3 includes both required chunks; fixed rerank scores select them. Lexical-only omits a relevant candidate, illustrating a ceiling reranking cannot overcome. This fixture does not prove universal reranker gains.

    Late filtering here occurs before consumers and illustrates starvation rather than universal safety. Production exposure can already occur if unauthorized content reaches fetch/rerank/log/provider paths first. Early eligibility improves candidate budgets, while approximate search and current-policy checks still need separate treatment.

    9. Exact, HNSW, IVF and PQ make different trade-offs

    Exact scans can suit small corpora, selective sets, accelerated batches or evaluation baselines despite scaling costs. HNSW uses layered proximity graphs, with breadth, connectivity and build settings affecting behavior. No universal search-breadth curve predicts recall/latency across data, filters and hardware.

    IVF assigns vectors to coarse cells and probes some cells before scoring candidates. More probes trade work for neighbor coverage; IVF-Flat over all cells can recover exact neighbors plus coarse-search overhead. PQ introduces a separate codebook approximation. Original-vector rescoring can refine candidate distances but cannot recover unscanned neighbors.

    ANN recall compares approximate and exact metric neighbors; relevance recall asks whether answer-bearing evidence was found. Perfect neighbor recall does not imply answer coverage. The point lab computes neighbor recall, while the ranked-list lab measures labeled evidence. Memory arithmetic separates payloads/IDs/codebooks without fabricated timing.

    10. Reranking, rewrites and HyDE need separate evidence

    Evidence funnels have candidate ceilings

    1. Retrieve broadly

      Retrieve bounded lexical/vector lists.

    2. Fuse and fetch

      Deduplicate IDs and fetch current authorized text.

    3. Rerank

      Score existing pairs; absent candidates remain absent.

    4. Pack

      Pack diverse relevant spans within context/output budgets.

    Every stage preserves scopes, versions and budgets rather than one universal top-k.

    Cross-encoders jointly score query/passage pairs, potentially improving precision at added cost/latency. They can fail or truncate; no candidate-depth recipe fits every task. Tune depths, batching, truncation and context slots under evaluations/budgets, and respect external reranker exposure boundaries.

    Rewrites can resolve follow-ups or split questions but may change intent, negation, units or identifiers. Retain originals, bound expansion and evaluate downstream evidence. HyDE retrieves using hypothetical text that can contain false details; never cite that hypothetical text as authoritative evidence.

    11. Pack conditions and evidence rather than only scores

    Deduplicate overlaps, align source versions and cover subquestions within budgets. Diversity and authorized adjacent/parent spans preserve exceptions/conditions. Repeated high-scoring copies can have poor evidence coverage. Reserve instruction, history, tool and output capacity instead of filling the model limit with passages alone.

    Position/distractor effects depend on models/tasks and need measurement. Preserve source spans and distinguish generated headers from raw evidence. Conflicting generations need canonical freshness policies, explicit conflicts or abstention rather than silent merging.

    12. Freshness and late-builder races

    Content updates, deletions and access changes are different events. Define generations, publication guards and manifests. Tombstones can stop exposure before eventual physical cleanup; late builds must not revive deleted content. Stable retry identities do not authorize obsolete overwrites.

    The lab separates publication guards from final delete/ACL checks. Stale content can remain authorized, so access checks do not repair freshness. Current content can carry stale ACLs, so version guards do not replace access control. This is a sequential race illustration rather than a distributed implementation.

    13. Authorization precedes text exposure

    Preserve access at exposure boundaries

    1. Resolve principals

      Use trusted identities and current policies.

    2. Eligible candidates

      Apply supported filters to reduce starvation.

    3. Fetch and revalidate

      Check liveness/access before text reaches consumers.

    4. Scoped exposure

      Scope reranking, prompts, logs, caches and previews.

    Filters, authority checks and cache scopes have related but distinct roles.

    Resolve identities/groups under current-policy contracts, attach ingestion metadata and filter eligible retrieval where supported. Candidate fetch/liveness revalidation can be necessary with stale indexes/caches. Models do not enforce permissions; caller group claims and post-generation removal cannot justify earlier forbidden exposure. Metadata, previews and logs can leak too.

    Answer, semantic, retrieval and prefix caches need scopes and freshness/version identities. Equal queries do not authorize cross-user sharing. TTLs do not guarantee immediate revocation; stronger contracts require barriers, invalidation/revalidation and authority-failure policies. Define access boundaries for long streams and later citation previews.

    14. Citation identities do not prove claims

    Preserve source generations/spans and access-checked preview contracts. Verify cited IDs were supplied/eligible and actually support the associated claims; valid links can still be unsupported citations. Generated summaries/hypothetical text do not become authoritative evidence by appearing in context.

    Insufficient evidence can warrant unknown/not-found or qualified responses rather than confident completion. Measure completeness, support and abstention separately. RAG source references are product evidence tied to retrieved documents.

    15. Long contexts and RAG can work together

    Bounded long context

    • Fits bounded documents and avoids some chunk-selection misses.
    • Still incurs context costs, distractors and access/freshness checks.

    Retrieval and tools

    • Select evidence or structured records from larger/changing corpora.
    • Has ingestion/candidate ceilings and operational overhead.

    Hybrid approach

    • Retrieve eligible parent documents for longer-context processing.
    • Choose using task quality, costs, latency and evidence coverage.

    Bounded documents can fit directly when size, access, cost and quality permit. Large changing corpora often need retrieval/tools, without a universal token cutoff. Caching can reduce some costs without eliminating memory, invalidation or quality issues. Retrieval can select a parent document for long-context processing.

    Compare end-to-end quality, costs, latency, access, freshness and evidence. Long contexts can avoid chunk misses but still face distractors/truncation; selective retrieval has candidate ceilings. Neither context-window marketing nor neighbor benchmarks suffice.

    16. Debug and operate by layer

    Label queries across tasks, languages and permission scopes, including absent answers, identifiers, paraphrases, multihop evidence, old revisions and adversarial documents. Measure each ingestion/relevance/ranking/context/answer stage; use exact-vector baselines separately for ANN recall. Choose ranking metrics appropriate to labels rather than conflating them with answer success.

    For cannot-find reports, trace source eligibility, ingestion/freshness, candidates, packed spans and model use. Fix the responsible stage and rerun slices. Blindly increasing top-k or model size can add cost/noise without fixing missing documents, parsing or access. Observe ingestion/visibility delays, tails, saturation and caches.

    Query costs include embeddings/rewrites, searches, fetching/authorization, reranking, generation and amortized indexing/storage. Offline work still costs resources. Version/canary migrations and define bounded failures/abstention when evidence or authorities are unavailable, keeping evaluation labels out of retrieval corpora.

    17. Questions with worked answers

    Documents contain an answer but RAG misses it. What should be checked?

    Trace source eligibility, parsing, candidates, reranking/packing and generation using labeled failures. Locate missing evidence before replacing models.

    Does perfect ANN recall imply perfect answers?

    No. Neighbor recall compares vector-distance rankings; exact neighbors can be irrelevant, stale or insufficient. Measure evidence coverage and supported answers separately.

    Can reranking recover evidence outside the candidate union?

    Not when it scores existing candidates only. Improve retrieval/depth/queries/chunks or retrieve additional authorized evidence. Reranker scores are not answer-correctness probabilities.

    How does RRF use raw similarity scores?

    It uses ranks through 1/(k+rank), with absent items contributing zero. Tune constants/weights/depths, deduplicate identities and evaluate rather than assuming universal gains.

    Can an equal-dimensional new embedding model query the same index?

    Only with verified representation compatibility. Equal dimensions do not establish geometry, metrics or template compatibility. Incompatible changes need separate generations, backfills/change catch-up and controlled cutovers.

    Is post-search filtering always leak-free?

    No when forbidden content already reached logs, rerankers or providers. Enforce eligibility and authoritative access at exposure boundaries, including caches/previews; starvation is a separate quality issue.

    What if an old builder finishes after deletion?

    Reject obsolete publication using generations/tombstones, propagate deletion and clean derived state/caches under contracts. Final checks can block exposure during lag; physical purge differs from logical visibility.

    Does a working citation link establish grounding?

    No. Verify eligible versions/spans actually support claims, including conflicts, freshness and preview access. Insufficient evidence can require abstention or qualification.

    Explain and compare the mechanisms

    These open questions connect terminology to state, assumptions and failure boundaries. Try an example from your own work before comparing the explanation.

    Which boundaries should guide RAG chunking?

    Start from real queries and document structure: headings, paragraphs, tables, code and evidence units. Small chunks can lose conditions or definitions; large chunks can dilute retrieval and crowd out other evidence. Overlap preserves some continuity while increasing duplicates, index size and repeated context. No universal token size fits every corpus.

    Retain revisions, offsets, structure, access labels and versioned chunk identities. Child retrieval followed by authorized parent or neighbor expansion can help when budgets allow. Evaluate evidence retrieval and grounded answers on paired query slices. Rechunking requires controlled index publication so stale revisions or deleted data are not reintroduced.

    How do hybrid retrieval and reranking complement one another?

    Keyword retrieval handles exact names, identifiers and rare terms; vectors find semantic matches but may miss exact tokens or sufficient evidence. Hybrid retrieval combines candidates, using calibrated fusion or rank-based methods such as RRF rather than arbitrarily adding incompatible raw scores. Deduplicate evidence identities while preserving diversity, access and freshness.

    Reranking improves ordering within retrieved candidates but cannot recover missing evidence without another retrieval step. Packing and generation can still lose or misuse evidence. Measure retrieval recall, ranking, access violations and answer support separately, and include reranking latency and cost in the end-to-end budget.
